Agent 的记忆按**时间尺度与作用范围**可分为短期记忆与长期记忆，业界也常按**内容形态**分为工作记忆、情景记忆、语义记忆与程序性记忆。工程上更常用的是按"存储位置"分类。

1) **短期记忆（Working Memory / Context）** —— 保存**当前任务**的上下文：原始目标、近期对话、工具调用与返回、中间产物、任务状态。它**通常就是上下文窗口本身**，因此天然受窗口大小限制。**实现方式**：随消息列表累积；配合**滚动裁剪**只保留最近 N 轮；配合**摘要压缩**把旧消息压成结构化摘要；把大体积中间产物**外置到文件系统或对象存储**，上下文里只留摘要 + 引用。

2) **长期记忆（Long-term Memory）** —— 跨会话、跨任务保留的信息：用户偏好、历史经验、领域知识、过往任务的结论。**实现方式的核心是"写入决策 + 检索决策 + 遗忘决策"三段**：写入时做**原子化事件抽取**并评估新颖性、重要性、置信度、可复用性，不合格的直接丢弃；检索时**多路召回**（语义向量 + 关键词 + 结构化过滤 + 图关系扩展）再重排；遗忘时按**时间衰减、访问频率、价值评分**淘汰，并把淘汰项**归档而非物理删除**。

3) **按内容形态的四类记忆**（认知科学划分，工程上常借用）。**工作记忆**是当前上下文，就是短期记忆；**情景记忆**是"具体发生过什么"（某次任务的完整轨迹与结果），实现上存事件日志；**语义记忆**是"客观事实与知识"（如"该用户用 MySQL"），实现上存带来源与置信度的事实条目；**程序性记忆**是"怎么做"（经验规则、SOP、失败教训），实现上存可复用的策略与反思文本。**区分情景与语义很重要** —— 情景记忆回答"那次发生了什么"，语义记忆回答"事实是什么"，检索策略与时效要求完全不同。

4) **记忆分层的存储选型**。情景记忆 → **事件日志 / 时序库 / 对象存储**（重写入、按时间检索）；语义记忆 → **向量库 + 结构化数据库**（向量做召回，字段做过滤与去重）；程序性记忆 → **规则库 / 知识图谱 / 文档仓库**（可版本化、可审阅）；工作记忆 → **上下文 + 外部 scratchpad**（临时文件、KV 存储）。

5) **知识图谱型记忆**是近年更受重视的形态。把"实体-关系-属性"显式建模，天然解决**多跳推理**（A 的同事的项目用了什么框架）、**实体对齐**（不同工具返回的对象是否指同一实体）与**冲突溯源**（同一属性有两个值时能看到各自来源与时间）。代价是**构建与维护成本高**，实体消歧困难。

6) **记忆必须带元数据才能用好**。每条记忆至少要有：来源、置信度、时间戳、有效期、作用域（会话 / 项目 / 用户 / 全局）、以及**实体链接**。没有这些元数据，冲突解决、时效判断、作用域隔离全都无从谈起。

7) **记忆的三条工程原则**。**写入要克制**（噪声是最大敌人，宁缺毋滥）；**冲突要显式处理**（时间优先、权威性优先、作用域优先、置信度优先，解决不了就澄清）；**读写两侧都要做冲突检测**（写入时查既有记忆、检索时查同批结果是否互相打架）。
