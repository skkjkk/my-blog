Agent Loop 是驱动 Agent 持续工作的**循环骨架**：模型反复地"感知当前状态 → 思考下一步 → 产生动作 → 观察动作结果 → 更新状态"，直到满足终止条件。它是所有 Agent 框架的公共内核，ReAct、Reflexion、规划-执行等范式都是在它之上做变体。

1) **典型步骤是六步循环**。第一步**构建上下文**：把系统提示、目标、可用工具、相关记忆、近期轨迹组装成提示；第二步**推理**：模型生成思考与动作；第三步**执行动作**：调用工具或产生输出；第四步**观察**：捕获执行结果与错误；第五步**更新状态**：把结果写回消息列表、更新任务状态与预算；第六步**判定终止**：检查是否完成、是否超限、是否需要重规划，不终止则回到第一步。

2) **终止条件是多重的，不是单一**。包括：模型给出最终答案、**验收条件被程序化校验通过**、达到最大步数、达到 token 或时间预算、连续多步无进展、检测到循环、或收到外部取消信号。**缺少多重终止条件是 Agent 失控的首要原因。**

3) **循环的本质是"受控的状态机"**。它看起来像 while 循环，但生产实现必须处理**幂等、重试、错误分类、状态持久化、断点恢复**。生产中的 Agent Loop 通常跑在**事件溯源**的引擎上，而不是一个简单的 while。

4) **单轮与多轮 Agent 的区别**。单轮是"一次调用 → 一次工具 → 一次回答"；多轮 Agent 的循环里，**模型的每一轮输出都只是下一步的输入**，没有哪一轮是最终答案，直到某轮触发了终止条件。所以**不能把某一轮的文本当作结果交付**。

5) **循环中的"思考"与"行动"要不要分离**。ReAct 风格把思考和行动写在同一次输出里；规划-执行分离风格则让规划器与执行器分属不同上下文。前者简单、后者在长程任务上更稳。

6) **工程上必须监控的循环内指标**：每步耗时与 token、工具成功率、**重复动作率**、无进展步数、上下文长度增长曲线、重规划次数。这些是线上定位"Agent 变慢/变贵/跑偏"的直接依据。

7) **循环与"自主程度"的关系**。循环可以完全自主（无人干预直到结束），也可以是**人在环**（关键步骤请求人工确认）。生产系统普遍采用人在环，因为完全自主的循环在错误场景下的代价不可控。
