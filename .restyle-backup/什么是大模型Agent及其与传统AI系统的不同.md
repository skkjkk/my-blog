大模型 Agent 是**以大语言模型为核心决策引擎**、能在环境中自主感知、规划、调用工具并持续行动以达成目标的软件系统。传统 AI 系统通常把"感知、决策、执行"拆成固定的流水线，由工程师显式编排；而 Agent 把**决策权交给了模型**，让它在运行时动态决定下一步做什么。

1) **最根本的区别是控制流的位置**。传统系统的控制流**在代码里**（每个 if/else、每条规则、每个流程节点都是人写好的）；Agent 的控制流**在模型里**（模型在运行时决定下一步）。这带来的直接后果是：**同一输入可能走出不同路径** —— 行为不再完全确定。

2) **传统 AI 是"一次性推理"，Agent 是"闭环迭代"**。传统系统输入固定、输出固定；Agent 通过"感知 → 思考 → 行动 → 观察"的循环不断修正方向，能处理**步骤数无法预先确定**的任务。

3) **传统 AI 通常没有副作用，Agent 有**。传统系统的输出是预测结果或建议；Agent 会真实调用数据库、修改文件、发请求、执行代码。因此 Agent 必须额外处理**权限、幂等、事务、审计、回滚** —— 这些是传统 AI 系统不需要考虑的。

4) **传统 AI 的组件是模型 + 特征工程，Agent 的组件是模型 + 工具 + 记忆 + 运行时**。Agent 多了"手"（工具）、"记性"（记忆）、"调控机制"（预算、终止、恢复）这三块。

5) **工程重心不同**。传统 AI 的工程重点是**数据与特征**；Agent 的工程重点是**上下文工程、状态管理、可靠性与可观测性**。这正是"Prompt Engineering 让位于 Context Engineering"的原因。

6) **可测试性变难**。传统系统的输出可用固定样本回归验证；Agent 的路径不确定，**必须建立任务集 + 多次采样 + 统计口径 + 确定性回放**才能回归。这就是 Agent 评测比传统模型评测复杂得多的原因。

7) **失败模式不同**。传统 AI 主要是**精度不够**（答错）；Agent 除了答错，还会**过程性失败** —— 选错工具、陷入循环、目标漂移、越权操作、烧掉预算。这些失败模式需要专门的检测与恢复机制。

8) **价值与成本的取舍**。Agent 适合**步骤不定、需要与环境交互、领域知识难以显式规则化**的任务；步骤固定的任务，传统流水线**更快、更便宜、更可控、更易测试**。**工程判断的标准是"这一步是否真的需要自主推理"** —— 成熟系统普遍是混合式的，把确定的部分用代码写死，只把需要灵活判断的部分交给模型。

9) **与传统 AI 的分界其实是渐进的**。推荐系统、搜索排序、画像推荐这些传统 AI 系统，只要引入"模型自主决定下一步调用哪个召回源或哪个策略"，就已经开始具备 Agent 的特征。**Agent 不是一个全新物种，而是 AI 系统设计中"自主性"这一维度的提升。**
