# 自建评论区 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 把博客的 giscus 评论换成本站自建的评论系统——匿名可评、数据在自己的 D1、后台可审核管理，并配上与公开可用相称的安全与异常处理。

**架构：** Cloudflare Worker 内新增一组 `/api/comments*` 路由（公共读写 + 管理端），读写 D1 六张表；纯逻辑（文本净化、加密签名、限流判定、内容分类）抽成 `worker/lib/*.js` 以便用 `node --test` 做单元测试。前端把 `Comment.astro` 换成"骨架 + 客户端渲染"，挂载逻辑复用 `Layout.astro` 里既有的 swup `page:view` 模式；后台在现有 `/admin` 增加一张评论卡片。

**技术栈：** Astro 5、Cloudflare Workers（`worker/index.js` 单入口）、D1（SQLite）、Tailwind + 既有 CSS 变量、`node --test`（Node 24 内置，不加依赖）。

**规格：** `docs/superpowers/specs/2026-11-01-comments-design.md`

**分支：** `main` 推送即自动部署上线，所以整个实现全程在 `feat/self-hosted-comments` 分支上进行，验收通过后由作者决定何时合并。

## 全局约束

- 不新增任何运行时依赖；单元测试只用 Node 内置 `node --test`（Node ≥ 20，当前 v24）。
- 全部代码 ESM；`worker/` 下不要 `require`。
- 建表语句一律 `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS`，可重复执行。
- 面向用户的文案一律简体中文，不用"错误 500"这类术语。
- 用户输入只经 `textContent` / `createTextNode` 落到 DOM，**任何情况下都不用 `innerHTML` 拼用户内容**。
- 公开接口绝不返回 `pending` / `spam` / 软删除内容，也不返回 `ip_hash`、`email_hash`、`identity_hash`。
- 时间统一 ISO8601 UTC 存储，前端转本地。
- 每个任务结束时 `pnpm test` 必须全绿；涉及页面/构建的任务还要 `pnpm check` 通过。
- 环境变量：`IP_SALT`、`COMMENT_COOKIE_SECRET`（必填 Secret），`TURNSTILE_SECRET`（可选）。

## 审查重点（Review Focus）

按最可能伤到读者的程度排序，每条都已在对应任务的测试里钉住：

1. **正文里的 HTML/JS 被执行**（`<img src=x onerror=…>`、`<script>`）→ 读者应看到原样文本，页面不得跳转/弹窗（任务 10 的 `linkify` 测试 + 渲染步骤强制 `textContent`）。
2. **超大请求体打爆 Worker**（有人 POST 5MB 正文）→ 应在读 body 前按 `content-length` 拒绝，返回 413（任务 7）。
3. **双击/网络重试产生重复评论**→ 同一 `clientId` 只能落一行，第二次返回同一条（任务 7）。
4. **待审/垃圾评论从公开接口泄漏**→ 列表接口只出 `approved`（任务 6）。
5. **深色模式下评论文字不可读**（写死颜色）→ 只用 `text-75`、`--primary`、`card-base` 等既有变量（任务 10 的检查清单）。

```js
import test from "node:test";
import assert from "node:assert/strict";
import { RATE_LIMITS, WINDOW_MS, rateVerdict } from "../../worker/lib/rate.js";

const now = 1_700_000_000_000;

test("无记录时放行", () => {
  assert.deepEqual(rateVerdict([], now), { allowed: true });
});

test("30 秒窗口内第二条被拒并给出 retryAfter", () => {
  const groups = [{ scope: "ip", window: "30s", count: 1, firstTs: now - 5_000 }];
  const v = rateVerdict(groups, now);
  assert.equal(v.allowed, false);
  assert.equal(v.window, "30s");
  assert.equal(v.retryAfter, 25);
});

test("未到阈值时放行", () => {
  assert.equal(rateVerdict([{ scope: "ip", window: "1h", count: 9, firstTs: now - 60_000 }], now).allowed, true);
});

test("达到阈值即拒", () => {
  assert.equal(rateVerdict([{ scope: "ip", window: "1h", count: 10, firstTs: now - 60_000 }], now).allowed, false);
});

test("全站闸门", () => {
  assert.equal(rateVerdict([{ scope: "site", window: "1h", count: 200, firstTs: now }], now).allowed, false);
});

test("多组同时命中时取最长等待", () => {
  const groups = [
    { scope: "ip", window: "30s", count: 1, firstTs: now - 1_000 },
    { scope: "id", window: "1h", count: 20, firstTs: now - 600_000 },
  ];
  const v = rateVerdict(groups, now);
  assert.equal(v.allowed, false);
  assert.equal(v.retryAfter, 3000);
});

test("窗口常量齐全", () => {
  assert.deepEqual(Object.keys(WINDOW_MS).sort(), ["1d", "1h", "30s"]);
  assert.equal(RATE_LIMITS["site:1h"], 200);
});
```

- [ ] **步骤 2：运行测试验证失败** — `pnpm test`，预期 FAIL

- [ ] **步骤 3：实现 `worker/lib/rate.js`**

导出 `WINDOW_MS = { "30s": 30_000, "1h": 3_600_000, "1d": 86_400_000 }`；
`RATE_LIMITS = { "ip:30s": 1, "ip:1h": 10, "ip:1d": 30, "id:30s": 1, "id:1h": 20, "site:1h": 200 }`；
`rateVerdict(groups, now)`：遍历 groups，取 `RATE_LIMITS[scope + ":" + window]`，若 `count >= limit` 则算 `retryAfter = ceil((firstTs + WINDOW_MS[window] - now)/1000)`，收集所有命中后返回 `{ allowed:false, scope, window, retryAfter }`（retryAfter 取最大值、最小 1）；否则 `{ allowed:true }`。
`rateCheck(db, scopes, now)`：对每个 scope 查 `SELECT window, COUNT(*) AS count, MIN(ts) AS first FROM comment_rate WHERE bucket = ? AND ts > ? GROUP BY window`（bucket 形如 `ip:<hash>`，时间阈值取 1d 窗口起点），合并成 groups 交给 `rateVerdict`。查询抛错时返回 `{ allowed:true, degraded:true }`（可用性优先）。
`rateRecord(db, scopes, now)`：对每个 scope × 每个窗口插入一行 `(bucket, window, ts)`，用 `db.batch()`。
