# 笔记规范（题库的唯一标准）

> 这份文档同时被三处消费：**人写笔记时的模板**、**`scripts/note-quality.mjs` 的体检规则**、**`scripts/enrich-notes.mjs` 的补全提示词**。
> 改规则时三处一起改，否则刷题页会退化回「答非所问」。

## 为什么要有规范

刷题页的答案不是另写一套，而是**直接从笔记正文里抽**（`src/utils/quiz-utils.ts`）。
所以「刷题体验差」＝「笔记结构差」：

| 刷题的症状 | 对应的笔记缺陷 |
| --- | --- |
| 点开答案答非所问 | 首段不是结论，是背景铺垫／寒暄／「这个问题要先从…说起」 |
| 只回答了一点，不够 | 首段只有一句话，后面的 `##` 小节没写内容，或者根本没分小节 |
| 「要点提纲」是空的 | 全篇没有 `##` 标题（旧笔记里 28 篇如此） |
| 提纲全是我看不懂的名词 | 小节标题写成了「基本用法」「注意事项」这种空壳，看不出抓没抓住 |
| 答案被截断在半句 | 首段太长（>600 字），抽答案时被 clamp 掉 |
| 自测完不知道自己漏了什么 | 笔记里没有「常见追问」「易错点」，没得查漏 |

## 一篇合格笔记的骨架

```markdown
---
title: 什么是 Java 的 CAS 操作？          # 就是题目本身，问句形式
published: 2026-10-23
description: "一句话摘要，20–60 字，自己写完，不留空、不留「…」截断"
tags: [并发编程]                          # 别写「面试」，那是噪音，题库里会被过滤
category: Java
section: note
draft: false
---

首段（**必写，60–200 字，直接回答问题**）：一句话结论 + 一句最关键的展开。
不要「这个问题很重要」「下面我们来…」，第一句就要能当标准答案。

## 它到底是什么            ← 定义/机制，讲清楚「是什么、怎么运作」
## 为什么要它 / 解决什么问题  ← 动机与对比（没有它之前怎么做，代价是什么）
## 关键要点                ← 3–6 条，每条一句话能独立复述（面试时能直接说出来）
## 代码 / 例子             ← 能跑或能看懂的最小例子；不适合写代码的用表格对比
## 常见坑与易错点           ← 3 条左右，写「错的直觉」+「正确的说法」
## 常见追问                ← 2–4 组，**一问一答两行，格式固定**（刷题页要解析它）
## 一句话记住              ← :::tip 包起来的收尾句，不超过 40 字
```

「常见追问」的格式是硬要求，刷题页靠它抽问答对：

```markdown
## 常见追问

**问：为什么不用 sleep(1)？**
**答：** 至少要真的让出 1 毫秒，实际唤醒还受时钟粒度影响，在需要快速响应的自旋里太钝。

**问：生产代码能这么写吗？**
**答：** 可以降低空转，但不能用来做线程协作，等条件成立要用 wait/notify 或阻塞队列。
```

也认 `**Q：…**` + `A：…`、`Q1：…` + `A：…` 这些写法；但**要点罗列（`1. 2. 3.`）不算追问**，解析不出来。

小节不必全都有，但**「首段结论 + ≥3 个实心小节 + 一句话记住」是硬要求**。

## 硬性红线（体检脚本会报错）

1. **不能有一级标题 `#`**：页面标题由 frontmatter 决定。
2. **段落、小节正文开头不能是「。」「，」「；」「：」**：这是旧笔记批量转换留下的手滑，读到会像结巴。
3. **代码围栏 ``` 与 `:::` 提示块必须配对**，表格列数必须一致。
4. **不允许 `1) 2) 3)` 这种老式编号**，用有序列表 `1.` 或 `-`。
5. **标题不得重复**（同一篇内、跨文件都算；重复会让 slug 表打架）。
6. **description 不能以「…」结尾**，也不能和标题复读。

## 评分口径（`node scripts/note-quality.mjs`）

| 检查项 | 权重 | 判定 |
| --- | --- | --- |
| 首段结论：60–300 字、无寒暄、句号收尾 | 25 | 不达标按比例扣 |
| 实心小节数（`##`，且每节 ≥80 字） | 20 | ≥3 满分，递减 |
| 关键要点可复述（列表/加粗句 ≥3 条） | 15 | — |
| 常见追问 / 易错点小节 | 15 | 有一项给一半，都有给满 |
| 一句话记住（tip 或收尾小结） | 10 | — |
| 例子：代码块或表格 | 10 | 概念类笔记可豁免（category 在白名单） |
| 红线（一级标题、残留标点、围栏/表格结构） | 5 | 破一条清零 |
| description 完整 | 5 | — |

分数 ≥85 = A（可直接刷），70–84 = B（能刷但要点薄），<70 = C（该重写）。

## 写新笔记的两条命令

```bash
pnpm new-post --title "什么是 GraalVM？" --category Java --tags 基础
node scripts/note-quality.mjs --only GraalVM      # 写完就体检，分数不够别发布
```
