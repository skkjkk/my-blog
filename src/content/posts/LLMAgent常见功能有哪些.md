LLM Agent 的常见功能可以按"能力形态"归为十一类：对话与问答增强、检索增强问答（RAG）、工具调用与 API 编排、多步骤任务执行、代码辅助与工程化、数据分析与洞察、计算机操作与 GUI 智能体、多 Agent 协作、长期记忆与个性化、规划与自主决策、生产运维与排障。另有流式输出、人在环、多模态三项能力贯穿全部功能，它们不是可选特性，而是决定 Agent 好不好用的体验基础。

## 能力全景：十一类功能与实现要点

把功能摊成一张表，面试时先给全景，再挑擅长的往下讲。

| 能力形态 | 典型场景 | 关键实现要点 |
| --- | --- | --- |
| 对话与问答增强 | 客服对话、知识咨询、内部答疑 | 在传统 RAG 之上加入多轮澄清、反问、答案溯源、拒答与转人工；核心是意图澄清与证据溯源 |
| 检索增强问答（RAG） | 文档问答、客服知识库、企业制度查询、内部知识检索 | 多路召回 + 重排 + 引用标注 + 时效性判断，并且检索不到时要明确拒答 |
| 工具调用与 API 编排 | 查询、写入、事务、通知 | 工具描述质量、参数校验、错误回填让模型自我纠正、并行调用降低延迟 |
| 多步骤任务执行 | 填表、报表生成、数据同步、批量处理、审批流转 | 任务分解、状态持久化、断点恢复、幂等，长流程要能从任意步骤续跑 |
| 代码辅助与工程化 | 代码生成、解释、审查、重构、修复、测试编写、CI 排障 | 读写代码库、执行与验证代码、基于真实编译与测试结果迭代 |
| 数据分析与洞察 | 自然语言查数、报表解读、趋势分析、异常归因 | 把意图翻译成查询、把结果做成结构化表格与图表、区分相关与因果 |
| 计算机操作与 GUI 智能体 | 表单填写、网页操作、跨应用协作 | 屏幕感知（截图解析）、坐标定位、动作执行与结果确认、失败重试 |
| 多 Agent 协作 | 主管式、链式、并行、路由、辩论等分工 | 任务契约、上下文隔离、结果汇总与冲突处理 |
| 长期记忆与个性化 | 记住用户偏好、历史决策、领域知识 | 写入筛选、检索排序、遗忘淘汰、冲突治理，并且对用户可见可控 |
| 规划与自主决策 | 复杂目标的分解与执行 | 分层规划、树搜索、反思改进；规划与执行分离、外部验收、局部重规划 |
| 生产运维与排障 | 告警响应、故障定位、自动化修复 | 人在环与强审计；排障路径无法预先穷举，正是 Agent 价值最大的地方 |

## 知识型能力：对话增强与 RAG

对话与问答增强是在传统 RAG 之上再加一层交互能力：**多轮澄清、反问、答案溯源、拒答与转人工**。它的实现要点是**意图澄清**与**证据溯源**——不确定就反问而不是猜，答案要能指回来源。

RAG 解决的是文档问答、客服知识库、企业制度查询、内部知识检索这类问题。关键能力是**多路召回 + 重排 + 引用标注 + 时效性判断**，以及**检索不到时的明确拒答**。拒答不是兜底话术，而是回答质量的一部分：宁可说不知道，也不要拿相邻文档凑一个看起来完整的答案。

## 执行型能力：工具调用与多步骤任务

工具调用与 API 编排负责调用外部 API 完成查询、写入、事务、通知。核心是**工具描述质量、参数校验、错误回填让模型自我纠正、并行调用降低延迟**。

多步骤任务执行覆盖填表、报表生成、数据同步、批量处理、审批流转。关键能力是**任务分解、状态持久化、断点恢复、幂等**——流程长的任务必须支持从任意步骤续跑，否则一次失败就等于全部重来。

## 专业型能力：代码辅助与数据分析

代码辅助与工程化包括代码生成、解释、审查、重构、修复、测试编写、CI 排障。关键能力是**读写代码库、执行与验证代码、基于真实编译与测试结果迭代**，而不是靠模型自己声称"已经改好了"。

数据分析与洞察处理自然语言查数、报表解读、趋势分析、异常归因。关键能力是**把意图翻译成查询、把结果做成结构化表格与图表、区分相关与因果**。最后一条最容易被忽略：用户问"为什么跌了"，看到相关性就下因果结论，是这类 Agent 最典型的错误。

## 落地型能力：Computer Use 与多 Agent 协作

计算机操作与 GUI 智能体（Computer Use）操作浏览器与桌面应用，完成表单填写、网页操作、跨应用协作。关键能力是**屏幕感知（截图解析）、坐标定位、动作执行与结果确认、失败重试**。这类任务对**可靠性要求极高**，因为误操作代价大。

多 Agent 协作按主管式、链式、并行、路由、辩论等模式组织多个角色分工。关键能力是**任务契约、上下文隔离、结果汇总与冲突处理**。多 Agent 不是越多越好，角色划分不清时，冲突处理的成本会超过并行带来的收益。

## 长期记忆、规划决策与生产运维

长期记忆与个性化记住用户偏好、历史决策、领域知识，提供个性化服务。关键能力是**写入筛选、检索排序、遗忘淘汰、冲突治理**，以及**用户可见可控**——用户要能查看与删除自己的记忆。

规划与自主决策面向复杂目标的分解与执行，包括**分层规划、树搜索、反思改进**。关键能力是**规划与执行分离**、**外部验收**、**局部重规划**。

生产运维与排障覆盖告警响应、故障定位、自动化修复。这是最能体现 Agent 价值的场景，因为**排障路径无法预先穷举**；但同时也最需要**人在环**与**强审计**。

## 贯穿所有功能的三项通用能力

- **流式输出**：提升感知体验，让用户在等待时就能判断方向对不对。
- **人在环**：在关键节点请求确认，把不可逆操作的决策权留在人手里。
- **多模态**：图像、语音、屏幕理解，决定 Agent 能不能处理真实世界里的输入。

**这三项不是可选功能，而是决定 Agent 好不好用的体验基础。**

## 功能选型的判断依据

判断某个需求该不该用 Agent，看三点：

1. **步骤是否可预先确定**：可确定就用工作流，不必上自主 Agent。
2. **是否需要与环境交互**：不需要就用普通调用，省掉规划与状态管理。
3. **错误的代价是否可控**：代价高就必须加强校验、加确认环节与人在环。

## 常见追问：边界与取舍

**Q：Agent 和 RAG 是什么关系？**
A：RAG 是一类能力形态，负责把外部知识引进来；对话增强则是在 RAG 之上再加澄清、溯源、拒答与转人工。Agent 则在这些能力之上组合工具、状态与规划。

**Q：什么需求不该上 Agent？**
A：步骤可预先确定的用工作流；不需要与环境交互的用普通调用；错误代价高的先加强校验与人在环，再谈自主性。

**Q：哪类功能最能体现 Agent 的价值？**
A：生产运维与排障，因为排障路径无法预先穷举；但它也最需要人在环与强审计。

**Q：长期记忆最难的部分是什么？**
A：不是存和取，而是写入筛选、冲突治理与遗忘淘汰，还要保证用户能看见、能删除。

## 易错点：四句话最容易说错

- **把"多 Agent 协作"当默认架构**：先问单 Agent 加工具够不够，角色不清的拆分只会把冲突处理成本抬上去。
- **只做检索和工具调用，不做拒答与溯源**：检索不到时硬答，比明确拒答对信任的伤害大得多。
- **对 Computer Use 的可靠性预期错位**：误操作代价大，必须补动作前确认与动作后结果确认，不能只看单步成功率。
- **长期记忆只写不治理**：没有写入筛选、遗忘淘汰、冲突治理，记忆越多越容易互相打架，用户也无法信任。

:::tip[一句话记住]
选型三问：步骤能预先确定吗、要跟环境交互吗、出错代价扛得住吗。
:::
