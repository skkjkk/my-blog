Thread.sleep 传入 0 表示不进行任何实质的等待，它的作用是让当前线程主动放弃 CPU 的时间片，从运行状态退回到就绪状态，让操作系统重新调度，这样那些优先级与它相同或者优先级更高的线程就有机会获得 CPU 执行机会。在长时间占用 CPU 而不主动让出的循环中，插入一次 sleep 零可以避免单个线程饿死其他线程。

需要明确的是，这只是一个让出机会的提示，并不保证一定发生线程切换。是否真正切换、切换给谁，都由操作系统的调度策略决定，当前线程完全可能在下一次被调度时马上又拿到 CPU，表现为继续执行。另外 sleep 零与普通的让出方法在语义上接近，但它仅仅是让出 CPU，并不释放已经持有的任何锁，这一点与 wait 完全不同。

实际使用中要谨慎，一般并不推荐依赖 sleep 零来做线程间的协作或顺序控制，因为它不提供任何同步语义，无法保证被让出的线程已经运行过，依赖它编写的逻辑在时序变化后就可能出错。它更多是作为降低单线程 CPU 空转带来的资源浪费、缓解高优先级线程饥饿的一种经验性技巧，而不是一种可靠的线程协调手段。
