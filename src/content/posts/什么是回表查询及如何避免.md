## 什么是回表查询

回表是指**通过二级索引查到主键值后，再回到聚簇索引中查一次完整行数据**的过程。InnoDB 的索引分两级：聚簇索引（叶子节点存放整行数据）和二级索引（叶子节点只存放主键值），因此**凡是用二级索引查找、且查询需要非索引列的字段，必然要再查一次。**

### 聚簇索引

InnoDB 的**主键索引就是聚簇索引**——叶子节点直接存放**整行数据**。所以**按主键查询只需一次 B+ 树查找就能拿到完整行**，这是 InnoDB 最重要的性能优势。

### 二级索引

除主键外的所有索引。叶子节点存放的是**索引列的值 + 主键值**（⚠️ **不是行地址**，与 MyISAM 不同）。

:::tip
**因此：二级索引查到的只是"线索"，要拿到完整行必须用主键再查一次聚簇索引——这一步就叫回表。**
:::

## 回表发生的时机

| 查询场景 | 是否回表 | 原因 |
|---------|---------|------|
| 走聚簇索引（`WHERE id = ?`） | 否 | 叶子节点直接存放整行数据 |
| 走二级索引，SELECT 字段全在索引中（覆盖索引） | 否 | 索引已包含所有需要的数据 |
| 走二级索引，SELECT 字段不全在索引中 | 是 | 索引叶子只有索引列 + 主键，缺的字段必须回表取 |

## 覆盖索引：最有效的避免手段

```sql
-- 假设索引是 idx_name_age(name, age)
SELECT name, age FROM user WHERE name = '张三';
```

只用到了 `idx_name_age` 这一个索引，**name 和 age 都在索引里** → **完全不用回表** → 称为覆盖索引。

:::caution
**这就是"回表查询怎么避免"的答案：让查询用到的所有字段都包含在同一个索引中。**
:::

## 索引数量与回表的连锁问题

### 一次查询只能走一个索引

每个索引都是一棵独立 B+ 树，**一次查询只能走一个索引**。如果"查条件用 A 索引、排序用 B 索引"，InnoDB 只能**选一个**（通常选过滤性更好的），**另一个索引就白建了**。

### 最左前缀原则

联合索引 `(a, b, c)`：

| 查询条件 | 索引命中情况 | 是否回表 |
|---------|-------------|---------|
| `WHERE a=? AND b=? AND c=?` | 完全命中 | 取决于 select 列是否都在索引中 |
| `WHERE a=? AND b=?` | 命中 a、b，c 失效 | 取决于 select 列是否都在索引中 |
| `WHERE b=?` | 完全失效（违反最左前缀） | 走全表扫描或其它索引 |

## 回表的性能代价

回表是**随机 IO**：二级索引里的主键值未必与聚簇索引的物理顺序一致，**每个主键都要去聚簇索引 B+ 树里"再定位一次"**。

- 回表 10 行 → 10 次随机 IO
- 回表 10000 行 → 10000 次随机 IO → **随机 IO 远慢于顺序 IO，可能比全表扫描还慢**

:::tip
**所以"用了索引反而更慢"的典型场景：命中索引但需要回表大量行**——此时优化器会评估成本，必要时直接全表扫描。
:::

## 避免回表的四种手段（按推荐度）

### ① 覆盖索引 ⭐⭐

最常用。让所有 select 列都在索引里。

### ② 索引下推（Index Condition Pushdown, ICP）⭐⭐

MySQL 5.6+，**在存储引擎层的索引上就能过滤**，减少回表次数（`EXPLAIN` 的 Extra 显示 `Using index condition`）。

### ③ 延迟关联 ⭐⭐

深分页时先在索引上取 id 列表，再回表。

### ④ 减少查询列

不写 `SELECT *`，只取真正需要的字段（这本质上就是在主动构造覆盖索引）。

## 用 EXPLAIN 确认是否回表

| Extra 字段 | 含义 |
|-----------|------|
| `Using index` | 覆盖索引，没有回表（好） |
| `Using where` | 有额外过滤条件 |
| 没有 `Using index` 且没有 `Using filesort`，key 不是 PRIMARY | 大概率发生了回表 |

:::tip
**更精确的验证：把 select 列改成索引里的列再看 Extra 是否变成 `Using index`。**
:::

## 面试怎么答

1. 原理（二级索引叶子只存主键值 → 必须回聚簇索引再查一次；覆盖索引是唯一的免回表路径）
2. 代价（回表是随机 IO，大量回表可能比全表扫描还慢）
3. 四种避免手段（覆盖索引、ICP、延迟关联、减少列）+ 用 EXPLAIN 的 `Using index` 验证。第二点能说出"回表是随机 IO"最能体现底层理解
