`String` 被声明为 `final`，是为了**保证不可变性**——类不可被继承、内部字符存储私有且不对外暴露，一旦创建，内容就再也改不了。而不可变性是 Java 语言层面刻意设计的核心特性：它带来的共享安全、哈希码缓存、常量池复用等收益，远大于"允许子类化 String"这个几乎没人真正需要的灵活性。

## 不可变性是怎么做到的：final 类 + 私有的字符数组

`java.lang.String` 的声明是 `public final class String`，类本身不可被继承；内部的字符存储是**私有且 final 的引用**（不同 JDK 版本里是 `char[]` 或者 `byte[]` 加一个编码标记，对使用者是等价的），对外**不暴露任何可以修改内容的字段或方法**。所有看起来会"改字符串"的操作——`substring`、`replace`、`concat`、`toUpperCase`、`+` 拼接——**都返回一个新对象**，原对象的内部数组一个字节都不会动。这三条加起来，"创建之后内容不再变化"才成为**类型级别的保证**，而不是文档里的一句口头约定。也正因为它是值语义的对象，String 才可以被自由地缓存、共享、当作 map 的键。

## `final` 的两层含义要分清

**类被 `final` 修饰** = 不可被继承，这是保证 String 不可变的那一层；**方法被 `final` 修饰** = 不可被重写，这是把"不可变契约"钉死的那一层。`String` 的 `equals`、`hashCode`、`length`、`charAt` 这些方法是值语义的承载者，只要它们的行为能被改，不可变就只是"约定"而非"保证"——子类完全可以重写 `length()`、`charAt()`、`equals()`、`hashCode()`，造出一个"看起来是 String、行为却不一样"的对象，然后把它塞进任何接受 String 的 API 里。严格说来，类已经是 `final`，这些方法就不必各自再标 `final`，真正起作用的是**类级 `final` 把整条继承链掐断**；方法级的 `final` 是同一件事更细粒度的表达。

## 安全性的根本保障：引用即内容

String 被大量用作**共享常量**：配置项、类路径、URL、SQL 语句、文件路径、锁对象的名字。这些值的特点是要被**传给一堆互不相识的代码**——框架、驱动、第三方库、日志组件。如果 String 可变，任何拿到引用的代码都能改它的内容，程序就再也无法推理"我手里的这个值到底是什么"：你在方法开头校验过的 SQL，可能在执行前被另一个线程改掉。**不可变让"引用即内容"成立**——拿到引用就等于拿到了那一刻的确定值，可以放心传给任何方法而不担心它被偷偷改掉，也因此**不需要防御性拷贝**（每次传参都复制一份的代价）。这条性质是整个 String 设计的出发点，下面所有收益都是它的推论。

## 哈希码可缓存：String 能当 HashMap 键的前提

`String` 把算好的哈希值存进内部的 `hash` 字段，下次直接读，不重算。因为内容不可变，这个缓存**永不过期**，省掉了每次查找都遍历一遍字符的开销。更关键的是**一致性**：HashMap 靠 `hashCode` 定位桶、靠 `equals` 确认命中，如果键放进 map 之后内容还能变，`hashCode` 就会跟着变，桶位置也变，于是这个键**在 map 里"查不到自己"**，`get`、`remove` 全部失效，entry 变成永远删不掉的垃圾。这是不可变带来的最实际的工程收益。

```java
Map<String, Integer> map = new HashMap<>();
String key = "user:1";
map.put(key, 100);

// 假如 String 可变，允许就地改内容：
// key.setCharAt(0, 'U');
// 那么 hashCode 随之改变 → 落点换了一个桶
map.get(key);    // 查不到自己
map.remove(key); // 也删不掉，entry 永远留在表里
```

## 线程安全天然免费

不可变对象**没有可变状态**，因此**不需要同步、不需要加锁、也不会被并发写坏**，可以安全地在多线程之间共享和缓存，不用付出任何同步成本。这正是 Java 把"值"和"缓冲区"拆成两种类型的原因：如果让一个类型同时承担"不可变的值"和"可就地修改的缓冲区"，那么为了线程安全，每次 `append` 都得加锁——那就是 `StringBuffer` 付出的代价；`StringBuilder` 更快，正是因为它去掉了那把锁，把并发责任交回给调用方。

| 类型 | 可变性 | 线程安全 | 典型场景 |
|---|---|---|---|
| `String` | 不可变 | 天然安全，无需加锁 | 常量、map 键、方法参数 |
| `StringBuffer` | 可变 | 方法级加锁，安全但有同步开销 | 需要多线程共享同一个缓冲区 |
| `StringBuilder` | 可变 | 不安全，由调用方保证 | 单线程内的循环拼接 |

## 常量池与 intern：这个机制能成立的前提

JVM 维护一个**字符串常量池**：编译期出现的字面量直接进池，运行期的 `intern()` 会拿内容去池里查，有就返回池里那个实例，没有就把当前字符串放进去再返回。这套机制的前提正是**内容不可变**——"内容相同就可以共用一个实例"只有内容永不改变时才是安全的等价替换。反过来，如果 String 可变，共用实例就意味着 A 改了自己的字符串、B 手里的值跟着变，池化立刻变成灾难；同时 `==` 也会彻底失去意义，因为"两个内容相同但引用不同"的字符串会同时存在。所以池化不是不可变的原因，而是不可变的**结果**。

## 锁对象：身份稳定才敢锁，但别锁字面量

`synchronized` 的锁状态记录在**对象头的 Mark Word** 里（monitor），跟着对象身份走，**跟 hashCode 没有关系**——这一点常被说混。不可变对象之所以适合当锁，理由不是"哈希值稳定"，而是**它的身份和语义都稳定**：不会出现"你锁的是这个内容，别人改完之后这把锁的含义变了"这种失控，所以不可变对象是天然的锁对象。但反过来要小心：**字符串字面量会被常量池复用**，两段毫不相干的代码写 `synchronized ("LOCK")`，锁住的是同一个实例，会互相阻塞甚至死锁。实践中不要拿 String 当锁，用一个专用的 `private static final Object LOCK = new Object();`。

## 代价与权衡：每次"修改"都要造一个新对象

不可变的直接代价是**连续拼接会产生大量中间对象**，短命对象一多，GC 压力就上来了。Java 的应对分两层：**编译期**，常量之间的拼接（字面量 `+` 字面量）会被直接折叠成一个常量，运行期零开销；**运行期**，单条表达式里的拼接会被编译成基于 `StringBuilder`（新版本是专门的字符串拼接指令）的形式，不会中间生成一串 String。但这些优化只覆盖单条表达式，**循环里的 `s += x` 每一轮都要新建对象**，规模一大就是平方级的复制量，必须显式改成 `StringBuilder`。所以"String 不可变"在日常开发里几乎不构成性能问题，**除非你在循环里用它拼接**。

## 为什么不用"可变 String + 防御性拷贝"来替代

这正是 `StringBuilder` 与 `StringBuffer` 的设计：需要就地修改的场景，就显式换成可变类型。**Java 的选择是"两种类型各司其职"，而不是让一个类型既可变又不可变**——默认的那个类型（String）承担"值"的角色，性能敏感处由调用方自己换。防御性拷贝算不上替代方案：它要求每次传参、每次取值都复制一份，开销随调用次数线性增长，而且只要有一处忘了拷贝，整套安全性就漏了。`final` 类还额外堵死了"子类破坏不可变契约"这条路，这也是 `final` 和不可变必须一起出现的原因。

## 常见追问

**Q：String 不可变，那 `s += "a"` 是怎么工作的？**
A：`s` 只是个引用，`+=` 是把它指向**新创建的** String，原对象还在（没人引用就被 GC 回收）。所以循环里 `+=` 越拼越慢，不是"在原对象上追加"。

**Q：不可变就等于线程安全吗？**
A：对象本身是安全的，但如果持有它的**引用变量**会被多个线程重新赋值，那个变量仍需 `volatile` 或同步来保护可见性与重排序。不安全的是"引用"，不是"对象"。

**Q：既然类已经是 `final`，为什么还说方法是 `final` 的？**
A：`final` 类本身就杜绝了重写，方法级 `final` 在这里是冗余但语义相同的表达，讲清"类级 final 掐断继承链"才是关键。另外还要记住第三条：**内部字段必须私有、且不对外暴露可变引用**，缺了这条，光加 `final` 也保不住不可变。

**Q：反射能改掉 String 的内容吗？**
A：旧版本可以靠 `setAccessible` 拿到内部数组再改，JDK 9 之后模块系统默认不开放 `java.lang` 的反射访问，这条路基本走不通，也不该走。真要可变请直接用 `StringBuilder`。

## 易错点

- **把"final 字段"当成"对象不可变"**：`private final char[] value` 只保证**引用不能换指向**，数组元素照样能改。String 的不可变靠的是私有 + 不暴露 + 不提供修改方法，不是那个 `final`。
- **以为 `synchronized` 依赖 `hashCode`**：锁状态在对象头里，跟哈希值无关。用 String 当锁的真正风险是**字面量被常量池共享**，不相关的代码锁到了同一个实例。
- **以为 `new String("a") == "a"` 是 true**：`new` 一定在堆上造一个新对象，`==` 比的是引用，结果是 false；比内容请用 `equals`。
- **以为编译器会把循环里的 `+=` 优化成 `StringBuilder`**：它只优化单条表达式，循环体里每一轮仍然新建对象，平方级的复制跑不掉。

## 一句话记住

:::tip
不可变是 String 的地基：共享安全、哈希可缓存、常量池成立，都建在它上面。
:::
