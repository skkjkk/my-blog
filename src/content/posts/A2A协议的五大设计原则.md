A2A 的设计原则可以概括为五条，它们共同决定了协议为什么长成现在这个样子。

1) **能力导向而非方案导向（Capability-based, not prescriptive）**。A2A **不规定 Agent 内部该怎么实现** —— 怎么规划、怎么用工具、用什么模型、什么架构，全部由 Agent 自主决定。协议只定义**它们之间如何交互**。这条原则让 A2A 能容纳形态各异的 Agent（从简单工作流到复杂自主系统），也是它能跨厂商存在的前提。

2) **Agent 自治（Agent autonomy）**。每个 Agent 保有自己的**内部推理、规划与执行逻辑**，对**自己的内部状态与执行方式负责**。协作方不介入也不需要了解其内部过程，只能通过 Agent Card 声明的契约与之交互。

3) **互操作性与可发现性（Interoperability & discoverability）**。通过**标准化的 Agent Card**、**标准数据格式**、**标准协议方法**，让不同厂商、不同语言、不同技术栈的 Agent 能够互相发现并协作。**协议的价值就在这里 —— 打破生态孤岛。**

4) **安全与隐私默认内建（Secure & private by default）**。**凭据不共享** —— 每个 Agent 用**自己的身份**跟对方通信，**凭据只随请求传递、绝不写在消息里**；**数据最小化** —— 只交换完成任务所必需的数据；**不强制委派** —— 对方可以在协议层明确声明"此任务我不接受"，调用方必须尊重。**这三条让 A2A 能在企业间使用而不牺牲信任边界。**

5) **可观测性与长期兼容（Observability & long-term compatibility）**。**任务状态可追踪** —— 任务的生命周期、状态流转、中间产物都有标准化的表达，便于端到端追踪与调试；**版本演进友好** —— 通过**能力协商**（协商出的能力集决定后续可用方法）保证协议向前兼容，老客户端与新 Server 可以共存，**不破坏既有集成**。

6) **五条原则的内在逻辑**。原则 1 和 2 保证了**异构 Agent 能共存**；原则 3 保证**它们能互相找到并说同一种话**；原则 4 保证**协同时不牺牲安全与隐私**；原则 5 保证**这套体系能被运维、被观察、且长期演进**。**缺任何一条，A2A 都无法在企业级场景落地。**

7) **面试答法建议**。先给"**A2A 是 Agent 之间的对等协作协议**"这一定位，再逐条给原则，最后**落到一句总结**："**它不关心你内部怎么做，只关心我们之间怎么对话、怎么互信、怎么长期一起活下去**。" 这比罗列协议细节更能体现理解深度。
