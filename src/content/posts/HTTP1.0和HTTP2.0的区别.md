两者的差别可以归纳为四个层面，分别是连接方式、传输格式、并发模型以及一些具体的功能特性。

首先是连接方式，HTTP 1.0 默认是短连接，每发送一个请求就要新建一次 TCP 连接，响应结束后再关闭，连接本身是带开销的，同一个主机上的多个请求无法复用连接。HTTP 1.1 之后引入了 keep-alive 持久连接才默认支持复用，而 HTTP 2.0 则把多路复用直接做在了协议层。

其次是传输格式，HTTP 1.0 和 1.1 的报文都是文本格式，头部是纯文本的键值对，每次请求都要携带完整的头部信息，开销明显。HTTP 2.0 改成了二进制分帧层，消息被拆成若干帧承载，每个帧带有帧头并且标记自己属于哪个流，这样头部就可以通过 HPACK 算法做压缩并被动态表复用，从而显著减少了重复头部的传输量。

第三是并发模型，这是最本质的差异。HTTP 1.1 虽然有持久连接，但同一连接上的请求必须按顺序串行返回，也就是必须等前一个响应收完才能发送下一个请求，这被称为队头阻塞。要规避它只能靠开多条连接，也就是域名分片或者建立多个连接，但连接数本身又受浏览器和服务器的限制，而且这样每个连接都要单独做 TLS 握手。HTTP 2.0 引入了一个连接上承载多个流的概念，每个流对应一个请求，不同的流之间可以并发交错传输、乱序到达，由接收端按流标识重新组装，因此从根本上消除了应用层的队头阻塞。

第四是其他功能特性，HTTP 2.0 支持流量控制与优先级机制，支持头部压缩，支持服务端推送能力，并且强制要求使用 TLS 加密。需要注意的是，虽然 HTTP 2.0 解决了应用层的队头阻塞，但底层 TCP 层的队头阻塞依然存在，一旦发生丢包，整个连接上所有流的数据都要等待重传，这也是后来 HTTP 3 改用基于 UDP 的 QUIC 协议要解决的问题。

另外还要澄清一个常见的误解，很多人把 HTTP 2.0 的多路复用说成是让并发数变多，实际上它的核心价值是让并发请求不必再依赖多条物理连接，从而可以在一个连接上高效地承载大量并发流，同时得益于头部压缩整体开销更低。
