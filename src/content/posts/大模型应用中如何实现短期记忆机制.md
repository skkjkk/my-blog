短期记忆解决的是"**当前任务内**模型需要记住什么"。它的实现位置就是**上下文窗口**，因此所有设计都围绕"**有限的窗口如何装下该装的东西**"展开。

1) **最朴素的形式就是消息列表**。系统提示 + 历史消息 + 当前输入，按顺序拼接成一个请求。问题是它**只增不减**，几轮之后就撑爆窗口。

2) **滑动窗口截断**。只保留最近 N 轮。**优点**是最简单、零成本、延迟最低。**缺点**是硬性丢失早期信息 —— 而早期往往包含原始目标与硬约束，这正是目标漂移的直接来源。**改进**：把"锚点"（系统提示、最初的目标陈述、最近一次目标重申）设为**永不参与截断**。

3) **摘要压缩**。用一个模型调用把旧消息压成摘要。**优点**是能保留语义要点、压缩比高。**缺点**是**有损且不可验证** —— 精确数值、ID、否定约束容易被丢掉；多次压缩会出现"摘要的摘要"，误差逐级累积；摘要本身要花钱和延迟。**改进**：用**结构化摘要**，固定字段如"已确认事实 / 已排除方案 / 关键参数 / 未决事项 / 硬约束"，并保留原文指针以便回溯。

4) **外部化 + 引用**。把完整内容（长文档、大工具返回、历史轨迹）存到外部存储，上下文里只放**摘要 + 可寻址引用**（文件路径、记录 id、行号范围），需要时再回读。**优点**是**无损**、不占窗口、支持随机访问。**缺点**是引入了对检索的依赖，且"什么时候该回读"本身是决策问题。**这是生产环境最稳的形态。**

5) **结构化抽取保留**。只保留特定类型的信息：实体与属性、工具调用及其结果摘要、决策点、约束清单、错误记录。**优点**是精准命中决策所需信息。**缺点**是抽取规则需按场景设计、通用性差。

6) **按重要性差异化保留**。给消息打重要性分数（是否含约束、是否被后续引用、是否与失败相关），低分压缩、高分原样保留。**优点**是比统一截断或统一摘要都优。**缺点**是打分本身有成本与误判风险。

7) **工具结果要在工具边界就裁剪**。这是短期记忆里**收益最高、成本最低**的一层 —— 长日志、大段 HTML、原始数据、整份文档，**在进入上下文前**就剥离标签、去重、只返回相关片段与计数。**不要等进上下文后再压缩。**

8) **上下文预算管理**。组装时设定**每类内容的 token 配额**（工具结果最多占 X%、检索内容最多占 Y%、历史轨迹最多占 Z%），超出按优先级裁剪。**没有配额就一定会失控。**

9) **位置效应**。长上下文中**中间部分的信息容易被忽略**（lost in the middle），所以高价值内容应放在提示的**靠前或靠后**位置。

10) **多轮与并行任务的隔离**。并行子任务各自的结果**不应全部堆进主上下文** —— 应当用**子 Agent 隔离**（各自上下文、只回结论），或写入**共享黑板**（主上下文只留索引与摘要）。这是短期记忆设计里最容易被忽视却收益极大的一条。

11) **一句话总结**。**短期记忆的本质是"有损压缩 + 外部化回退"** —— 关键不在压得多狠，而在**该留的绝不丢（精确值、ID、否定约束、未决问题）**，且**每一步都能回溯到原文**。
