一个 LLM Agent 的基本架构可以拆成五个组成部分加上贯穿其间的运行时控制。

1) **大模型（LLM）** —— 系统的**决策核心与推理引擎**。负责理解意图、分解任务、选择工具、生成参数、组织最终答案。它通常通过统一接口抽象（对话、结构化输出、工具调用、嵌入、重排），以便在不同环节选用不同规格的模型 —— 强模型做规划与复杂推理，便宜快模型做执行与格式转换。

2) **提示与模板层（Prompt）** —— 系统提示、角色设定、任务描述、工具使用规范、输出格式约束。**这里的文本质量直接决定行为质量**：模糊的指令导致不可预测的行为，明确的指令与示例则显著提升稳定性。此外还包含**上下文组装**（决定每一轮放什么进窗口），这在工程上往往与提示模板合为一层。

3) **工具（Tools）** —— Agent 的"手"。包括**工具定义与描述**（名称、功能说明、参数 JSON Schema）、**执行引擎**（真正调用外部系统）、以及**结果处理**（裁剪、摘要、错误规范化）。工具描述就是给模型看的提示，**命名与描述的准确度往往比换更强的模型更能提升工具选择准确率**。

4) **记忆（Memory）** —— 分短期与长期。**短期记忆**保存当前任务上下文（目标、近期轨迹、中间结果），本质上是上下文窗口加裁剪与摘要；**长期记忆**跨会话保存用户偏好、历史经验、领域知识，需要写入筛选、检索、遗忘与冲突治理。记忆解决"**装不下**"与"**接不上**"两个问题。

5) **状态管理（State）** —— 任务的状态与进度：任务树、子任务状态机、已完成产物、预算账本、验收结果。**状态必须外置到外部存储**，否则长程任务无法恢复、无法回滚、无法被外部观察。

6) **运行时控制（Runtime / Agent Loop）** —— 驱动循环的那部分确定性代码：组装上下文、调用模型、解析动作、执行工具、更新状态、判定终止、处理重试与降级、记录轨迹。**它是"确定的一半"，与模型这个"不确定的一半"配合。**

7) **五者的关系**。运行时控制是**骨架**，模型是**大脑**，工具是**手脚**，记忆提供**历史与经验**，状态提供**进度与可恢复性**。任何一环缺失，系统都会退化：没有工具就只是问答，没有记忆就只是单轮，没有状态就无法长程，没有运行时控制就无法治理。

8) **架构上还有两个常被单列的横切关注点**。**可观测与评估**（轨迹记录、指标、回归）以及**安全与权限**（能力令牌、工具网关、审计）—— 它们不改变主结构，但决定系统能否上生产。
