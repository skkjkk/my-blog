内部类是**定义在另一个类内部的类**，按定义位置分为成员内部类、静态内部类、局部内部类和匿名内部类四种。它编译后会生成自己独立的 class 文件，但仍被登记为外部类的成员，**并不是顶层类**，Java 的单继承约束对它同样成立。内部类最大的价值是能直接访问外部类的私有成员，并把只服务于外部类的辅助逻辑收拢在一起；代价是非静态内部类会隐式持有外部类实例，生命周期错配时可能让外部类无法被回收。

## 定义与编译后的形态

内部类写在另一个类的花括号内部。编译之后它会单独产出一个 class 文件，命名规则是外部类名接 `$` 再接内部类名：外部类 `Outer` 里的 `Inner` 生成 `Outer$Inner.class`，匿名内部类按出现顺序生成 `Outer$1.class` 这种名字，局部内部类则带上序号和本地类名。

这里需要纠正一个常见误解：**class 文件独立，不等于它就是顶层类**。编译结果里带有 `InnerClasses` 属性，把内部类登记为外部类的成员；成员内部类的构造器还隐式多一个指向外部类实例的参数，所以 `new Inner()` 的真实调用形态是带着一份外部类引用进去的。

正因为如此，Java 的单继承约束对内部类一样成立：内部类同样只能 `extends` 一个类，想表达多种能力只能靠实现多个接口，不会因为写在外部类里就获得多继承。

## 四种内部类的区别

四种形态的差别集中在三件事上：能不能脱离外部实例存在、怎么创建、能访问外部类的哪些成员。

| 类型 | 定义位置 | 是否持有外部实例 | 创建方式 |
| --- | --- | --- | --- |
| 成员内部类 | 外部类的成员位置，不带 `static` | 持有，可用 `Outer.this` 指名 | `outer.new Inner()` |
| 静态内部类 | 外部类的成员位置，带 `static` | 不持有 | `new Outer.Inner()` |
| 局部内部类 | 方法或代码块内部 | 视所在方法是否为实例方法而定 | 只能在方法内部 `new` |
| 匿名内部类 | 表达式位置，与 `new` 同时定义 | 在实例上下文中持有 | `new 接口/父类() { ... }` |

成员内部类定义在外部类的成员位置，可以直接访问外部类的所有成员，包括 `private` 修饰的私有成员，不需要加任何修饰符；它的实例必须依附于一个外部类对象，所以创建时要写 `outer.new Inner()`，在内部要指明外部实例时用 `Outer.this`。

静态内部类用 `static` 修饰，**不依赖外部类的实例**，因此它只能访问外部类的静态成员，创建时也不需要外部对象。局部内部类定义在方法内部，作用域仅限于所在方法，出了方法就不可见。匿名内部类是在创建对象的时候临时定义的，没有名字，一般用来一次性实现某个接口或者覆盖某个方法，也因此不能写构造器，需要初始化逻辑时用实例初始化块。

## 为什么需要内部类

如果没有内部类，一个只服务于某个类的辅助逻辑只有两个去处：单独建一个顶层类，或者直接塞进外部类的方法体里。前者的代价是把实现细节暴露到包级别，谁都能 `new` 出来；后者的代价是逻辑一复杂，外部类就被撑得难以阅读。

内部类解决的正是这个矛盾：源码层面它被收进外部类的花括号里，作用范围一目了然，同时又是一个完整的类型，可以继承、可以实现接口、可以作为参数和返回值传递。再加上编译器为内外类互相访问私有成员生成的合成访问器（synthetic accessor，常见的 `access$000` 一类方法），内部类可以合法读写外部类的 `private` 字段，外部类也能反过来访问内部类的私有成员，这是两个顶层类之间做不到的。

这种「对外隐藏、对内互通」的组合，让它天然适合承载回调和事件监听：给按钮注册点击事件时，匿名内部类可以把处理逻辑直接写在调用现场，不必为只用一次的行为单独建类。并发编程里用匿名 `Runnable` 或 `Callable` 提交任务、流式处理里用 lambda 或匿名内部类表达映射与过滤，都是同一个思路。JDK 集合类里也能看到这个取舍：`Map` 的节点实现是静态内部类，不持有外部引用；集合的迭代器多是成员内部类，因为它本来就要读外部集合的状态。

## 代码：三种写法的最小例子

下面这段代码同时展示成员内部类、静态内部类和匿名内部类，重点看三处：`count` 是外部类的私有字段却能被成员内部类直接读写；静态内部类访问不到它；匿名内部类里的 `step` 是方法局部变量，必须事实上不再修改。

```java
public class Outer {
    private int count = 10;

    // 成员内部类：隐式持有外部类实例
    class Member {
        void inc() {
            count++;                                // 直接访问外部类私有字段
            System.out.println(Outer.this.count);   // 显式指明是外部类的字段
        }
    }

    // 静态内部类：不持有外部类实例，只能访问静态成员
    static class Nested {
        void show() {
            System.out.println("no outer instance");
        }
    }

    Runnable callback() {
        final int step = 2;   // 局部变量被匿名内部类捕获，必须事实上不可变
        return new Runnable() {          // 匿名内部类：一次性实现接口
            @Override
            public void run() {
                System.out.println(count + step);
            }
        };
    }

    public static void main(String[] args) {
        Outer outer = new Outer();
        Outer.Member member = outer.new Member();  // 依赖外部实例
        Outer.Nested nested = new Outer.Nested();  // 不依赖外部实例
        member.inc();
        nested.show();
        outer.callback().run();
    }
}
```

## 关键要点

- **内部类是独立的类型，但不是顶层类**：各自生成 `Outer$Inner.class`，编译结果里登记为外部类的成员。
- **能访问外部类私有成员靠的是编译器的合成访问器**，不是 JVM 给了内部类特殊权限，也不是它会打破封装。
- **静态内部类与成员内部类的分水岭是「要不要外部实例」**：只需要外部类的静态成员时优先用静态内部类，可以避免无谓的引用。
- **成员内部类用 `outer.new Inner()` 创建，静态内部类用 `new Outer.Inner()` 创建**，这是面试里最容易被追问的语法点。
- **单继承限制不变**：内部类只能继承一个类，要多种能力就实现多个接口。

## 常见追问

**Q：内部类会破坏封装吗？它都能碰 `private` 了。**
A：不会。合成访问器由编译器生成，属于编译器与 JVM 之间的约定，源码层面外部类和内部类的可见性规则没有被放开；其他类仍然无法直接访问那些 `private` 成员。

**Q：成员内部类和静态内部类怎么选？**
A：看它是否需要外部实例的状态。需要读写外部对象的字段就用成员内部类；只是逻辑上属于这个类、不依赖具体实例（比如 Builder、纯数据结构、工具型嵌套类）就用静态内部类，避免多一层引用。

**Q：匿名内部类和 lambda 是不是可以互换？**
A：功能接口（只有一个抽象方法的接口）两处都能写，lambda 更简洁。但匿名内部类还能继承普通类、覆盖多个方法、持有自己的实例状态，`this` 指向自身而不是外部类，这些是 lambda 做不到的。

**Q：局部内部类和匿名内部类为什么要求局部变量是 `final` 或事实上不可变？**
A：它们捕获的是局部变量的副本，为了保证「代码里看到的变量值」始终一致，语言层面要求这个变量在赋值后不再改变；否则内外看到的值会分叉。

## 易错点

- **把「有独立 class 文件」当成「顶层类」**。错。它被 `InnerClasses` 属性登记为外部类的成员，构造器还隐式携带外部实例引用，这跟顶层类正好相反。
- **以为内部类能多继承**。错。`class Inner extends A, B` 依旧编译不过，内部类的身份不会松动单继承规则。
- **以为静态内部类也能访问外部类的实例字段**。错。它没有外部实例可用，只能访问外部类的静态成员，写了实例字段会直接编译报错。
- **在长生命周期的地方持有非静态内部类实例**。比如把它放进静态集合或缓存里，外部对象就被一起钉住回收不掉，看上去像外部类泄漏；这类场景应改用静态内部类或不持有外部引用的写法。

:::tip
内部类是收进外部类的独立类型，靠访问器互通私有成员，不需要外部实例就用静态内部类。
:::
