A2A（Agent2Agent）是由 Google 发起并逐渐成为社区标准的**Agent 间通信协议**，用于让**独立的、可能由不同团队开发、部署在不同厂商基础设施上的 Agent 相互发现、协商与协作完成任务**。MCP 解决的是"Agent 如何接入工具与数据"，A2A 解决的是"Agent 如何与另一个 Agent 协作"。

1) **解决的问题完全不同**。**MCP 是纵向的**（应用 ↔ 工具/数据），把能力接入统一化；**A2A 是横向的**（Agent ↔ Agent），把协作标准化。一个 Agent 既可以作为 MCP Client 使用别人的工具，也可以作为 A2A Server 被别人调用。

2) **核心概念是 Agent Card**。每个 Agent 用一张**机器可读的 JSON 卡片**公开自己的能力：名称、描述、能力列表、支持的技能与输入输出模式、认证方式、服务端点 URL。这相当于 Agent 的"名片 + 能力契约 + 自我介绍"，让别的 Agent 能**在运行时动态发现**它。

3) **核心原语是 Task（任务）**。协作以一个**有状态、有生命周期的任务**为单位，Task 贯穿从创建到完成的整个过程，过程中有状态更新、有**流式的中间产物**（Artifact）推送、有多轮消息往来。这与"一次 HTTP 请求-响应"的模型完全不同。

4) **协作模式更丰富**。除了"请求-响应"，A2A 还支持**流式更新**、**多轮交互**（对方可以反问澄清）、**任务委托与转交**、以及异步长任务。

5) **与 MCP 的互补关系**。实践中一个典型 Agent 会**同时是 MCP Client 和 A2A Server**：它通过 MCP 拿到本地工具与数据，通过 A2A 把需要专业能力的部分委托给远端专家 Agent。**MCP 管"手"，A2A 管"同行"。**

6) **A2A 特有但 MCP 没有的难题**。因为对手方是 Agent 而非工具，需要解决**信任与身份**（对方 Agent 是否可信、如何认证）、**能力发现与匹配**（从大量 Agent Card 中选出合适的一个）、**跨组织的数据与责任边界**、以及**跨厂商的语义互操作**。MCP 因为调用方是自己写的程序，这些问题不突出。

7) **Agent Card 的作用**。它既是**发现机制**（别人怎么找到你），也是**契约**（你的输入输出长什么样、调用要什么凭证），更是**信任凭据**（能力描述越具体，调用方越容易判断是否适合）。

8) **成熟度与现状**。A2A 规范由 Google 发起并捐赠给开源基金会，与 MCP、AGNTCY 等共同构成了 Agent 互联生态。它的价值更多体现在**跨组织、跨厂商**的长程协作场景；在**单组织内部**的多 Agent 编排，直接用代码框架（LangGraph、AutoGen、Semantic Kernel 等）往往更简单可控。

9) **一句话区分**。**MCP 让 Agent 拥有"工具"，A2A 让 Agent 拥有"同事"。**
