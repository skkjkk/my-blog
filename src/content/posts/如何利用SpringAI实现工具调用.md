工具调用（Tool Calling / Function Calling）是指模型不直接输出答案，而是输出一个**结构化的"调用哪个工具、参数是什么"的请求**，由宿主程序真正执行后把结果回传，模型再基于结果继续输出。**模型只表达意图，执行权始终在程序手里。**

1) **完整流程是四步**。注册工具（名称 + 描述 + 参数 JSON Schema）→ **模型决策**（返回 tool_calls：工具名 + JSON 参数）→ **宿主执行**（解析、校验、真正调用、捕获成功/失败）→ **结果回填**（按 tool_call_id 组织成 tool 消息追加，模型继续推理）。**模型不执行任何动作。**

2) **工具描述就是给模型的提示**。模型选哪个工具完全依赖你的描述与 schema —— 描述含糊、职责重叠、命名不当都会直接导致选错。**提升工具选择准确率，改描述往往比换更强的模型更有效。**

3) **Spring AI 的实现路径**。用 `@Tool` 注解声明方法，用 `@ToolParam` 描述参数，**方法签名自动生成 JSON Schema**；把方法放入 `ChatClient`（或 `ChatModel`）并绑定到请求，模型返回的 tool call 会由 Spring AI **解析成方法调用并通过反射真正执行**，再把结果回传给模型继续对话。

4) **Spring AI 的关键工程优势**。**① 声明式** —— 业务方法加注解即可成为工具，不需要手写 schema；**② 框架统一管理调用循环**（`ToolCallingManager` 负责解析与执行、结果回填、多轮衔接），**开发者不用自己写 while 循环**；**③ 与 Spring 生态集成**（依赖注入、AOP、事务、配置管理、`@Configuration` 声明 `ToolCallback`）；**④ 抽象隔离** —— 底层可换 OpenAI、Anthropic、Ollama、Vertex AI 等多家模型。

5) **使用上的注意点**。**参数校验仍需自己做** —— 注解生成的是结构约束，语义与业务约束（如金额上限、账号归属）要靠 `@Tool` 方法内部或 AOP 校验；**工具数量要控制**，过多会稀释注意力；**工具执行要有超时与异常处理**，并把**可诊断的错误**回传模型；**不要把敏感信息写进工具描述或参数回显**。

6) **Spring AI 中做多轮工具调用的方式**。把 `ChatClient` 与工具绑好，请求时指定 `toolCallbacks`；Spring AI 会自动完成"模型 → 工具 → 回填 → 模型"的循环直至模型不再请求工具。**需要精确控制时，可用 `ToolCallingManager` 手动介入**，自行决定是否继续循环、何时终止。

7) **与 MCP 的关系**。Spring AI 同时支持 **MCP Client**（把 MCP Server 的工具接入 Spring 应用），**在模型侧它们最终都表现为同一套 tool call 机制**。因此可以**混用**：一部分工具用 `@Tool` 本地声明（简单、无需部署），一部分通过 MCP 接入（复用生态），Spring AI 统一编排。

8) **生产环境的补充**。工具执行应走**独立的权限与限流层**（不要在业务方法里散落权限判断）；要加**幂等键**防重复副作用；工具返回值要**裁剪**再回填；**副作用类工具要有人在环确认**。Spring AI 提供了相应的拦截机制（如 `ToolCallAdvisor`）可挂载治理逻辑。

9) **常见错误**。**把工具描述写得太笼统**（模型选不准）；**忘记回填工具结果**（模型拿不到结果就自己编）；**工具内部抛异常导致整个循环中断**（应捕获并转成可诊断消息）；**在工具里做重逻辑**（应该先做参数校验，快速失败）。
