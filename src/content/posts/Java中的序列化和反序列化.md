序列化就是把**对象的状态**转换成字节流的过程，反序列化就是这个过程的逆操作，把字节流还原回对象。它们的核心价值在于让 Java 对象能够脱离 JVM 的内存，跨越进程和网络的边界去传输或者存储，最常见的用途包括网络通信、远程调用、缓存落盘以及深拷贝。

在标准实现里，只要类实现了 `Serializable` 标记接口，就可以用 ObjectOutputStream 的 writeObject 方法写出、用 ObjectInputStream 的 readObject 方法读回。这里有几个容易被追问的细节。第一，序列化只保存对象的**实例状态**，静态字段属于类级别信息不会被序列化，被 `transient` 修饰的字段也会被忽略。第二，类必须声明 `serialVersionUID`，它相当于序列化的版本契约，序列化时会把它的值一并写入字节流，反序列化时如果版本不一致就会抛出 InvalidClassException，所以显式声明它可以让版本演进更可控。第三，反序列化是**绕过构造器直接创建对象**的，这意味着构造器里那些校验逻辑不会被执行，反序列化不可信数据时存在安全风险，这也是近年很多框架在逐步弱化甚至淘汰 Java 原生序列化，转而使用 JSON、Protobuf、Kryo 这类更可控的格式的原因。第四，如果类中包含不可序列化的字段，需要用自定义的 writeObject 和 readObject 方法来指定如何处理。

实际项目中还要注意，序列化会完整保留对象的图结构，如果对象之间存在循环引用，也需要正确处理，否则可能造成栈溢出或者体积异常膨胀。
