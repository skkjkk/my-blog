接口和抽象类都是 Java 用来描述抽象行为的机制，但设计意图完全不同。接口描述的是**能力**，表达"一个类型能做什么"，是横向的能力契约；抽象类描述的是**共性**，表达"一族类型在实现细节上共享什么"，是纵向的模板继承。类可以实现多个接口但只能继承一个抽象类，这个根本约束决定了两者的定位不同。

语法层面，接口在 Java 8 之后可以包含默认方法和静态方法，也就是可以直接写实现逻辑，而抽象类依然可以包含抽象方法、普通成员变量和构造方法。在访问控制上，接口的字段只能是常量，隐式是 public static final；接口中的默认方法隐式是 public；抽象类的成员则可以自由使用各种访问修饰符，抽象方法也允许设置 protected。构造函数只有抽象类有，接口没有构造方法，也就无法保存接口对象的实例状态。

多态的实际表现也有差别。接口的字段是隐式常量，多个接口出现同名字段时实现类必须显式指明用哪个，容易产生歧义；抽象类的字段由子类直接继承，不存在这种冲突。另外接口方法默认是虚方法，调用走虚方法表动态分派，抽象类虽然也支持重写，但由于它带有具体实现和状态，子类通常也无法完全摆脱父类的行为约束。

实践中的选择原则是：如果多个不相关的类型需要共享同一组能力，用接口；如果多个类型在实现方式上高度相似、需要复用代码或者需要保存共同的实例状态，用抽象类。一个常见的反模式是给接口塞大量默认方法，最后接口变成一个庞大的实现集合，这既破坏了实现者的自由，也让接口难以演进。
