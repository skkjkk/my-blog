接口和抽象类都是 Java 用来描述抽象行为的机制，但设计意图完全不同。接口描述的是**能力**，表达"一个类型能做什么"，是横向的能力契约；抽象类描述的是**共性**，表达"一族类型在实现细节上共享什么"，是纵向的模板继承。类可以实现多个接口但只能继承一个抽象类，这个根本约束决定了两者的定位不同。

## 两种抽象：能力契约与共性模板

接口回答的问题是"你能做什么"。它给类型贴标签：一个类只要实现了 `Comparable`，就承诺能被比较；只要实现了 `Serializable`，就承诺能被序列化。实现者之间不需要有任何关系，一个 `String` 和一个 `File` 都可以是 `Comparable`，它们共享的只是这一组能力。

抽象类回答的问题是"我们共享什么"。它描述的是一族类型在结构上的共性：共同的字段、共同的构造过程、共同的骨架流程。子类之间天然是"是一个"的关系，继承抽象类意味着复用父类已经写好的那部分实现，同时被父类约束住行为。

所以两者的差别不在"能不能写实现"，而在**抽象的方向**：接口是横向扩展能力，抽象类是纵向复用实现与状态。

## 语法上的硬差别

| 维度 | 接口 | 抽象类 |
| --- | --- | --- |
| 实现/继承数量 | 一个类可以实现多个接口 | 一个类只能继承一个抽象类 |
| 成员变量 | 只能是常量，隐式 `public static final` | 普通成员变量，可保存实例状态 |
| 构造方法 | 没有构造方法 | 有构造方法，子类通过 `super` 调用 |
| 方法实现 | Java 8 起支持默认方法与静态方法，Java 9 起支持私有方法 | 抽象方法与具体方法都可以有 |
| 访问修饰符 | 抽象方法与默认方法隐式 `public`，不能降低可见性 | 成员可自由使用各种修饰符，抽象方法允许 `protected` |
| 能否实例化 | 不能 | 不能，但子类可实例化并带上父类状态 |

表里最容易被忽略的是「方法实现」和「构造方法」这两行：接口从 Java 8 起确实能写方法体了，但它依然**没有构造方法、没有实例字段**，也就无法保存接口对象的实例状态。抽象类有构造方法，`Bird b = new Sparrow("jack")` 这条链上父类的构造先执行，状态是从父类那里一路继承下来的。反过来说，接口连"每个实现类各持一份状态"这件事都做不到，因为接口里的字段只有一份，被所有实现类共享。

## 多态与字段歧义

接口方法默认是虚方法，调用走**虚方法表**动态分派：编译期看到的是 `Flyable`，运行期执行的是实际实现类的方法。抽象类同样支持重写、同样走虚方法表，区别在于它带着具体实现和状态，子类通常无法完全摆脱父类的行为约束——父类里写死的模板流程、`final` 方法、构造期做的事，子类都得照单全收。

字段上的差别更具体。接口的字段是隐式常量，当两个接口出现同名字段时，实现类里直接写 `SIZE` 会**产生歧义、编译不过**，必须显式写成 `InterfaceA.SIZE` 或 `InterfaceB.SIZE` 指明用哪一个；抽象类的字段由子类直接继承，不存在这种同名冲突问题。同理，如果两个接口提供了同签名的默认方法，实现类必须自己重写并把冲突解决掉，不能指望编译器替你挑一个。

## 怎么选：四个判断信号

- 多个**不相关**的类型需要共享同一组能力，用接口。它们之间没有"是一个"的关系，只是都满足某个契约，比如都能被序列化、都能被比较。
- 多个类型在实现方式上**高度相似**、需要复用代码，用抽象类。把共同的分支逻辑、模板骨架写在父类里，子类只填差异部分。
- 需要保存**共同的实例状态**或者共同完成初始化，用抽象类。接口没有构造方法也没有实例字段，这件事它做不了。
- 两者也可以配合：抽象类实现接口，先把接口的一部分实现掉，再让子类只补剩下的部分。这既保留了接口的多实现能力，又复用了代码。

一个常见的反模式是给接口塞大量默认方法，最后接口变成一个庞大的实现集合，这既破坏了实现者的自由（默认方法冲突、被迫继承一堆不想要的行为），也让接口难以演进。

## 代码：接口定义能力，抽象类提供共性

下面这段把前面的差别都落在语法上：接口里只能有常量、抽象方法和默认方法，没有任何状态；抽象类则带有字段和构造方法，还允许用 `protected` 修饰抽象方法，把实现细节留给子类。`Sparrow` 只能 `extends` 一个抽象类，却可以顺手实现任意多个接口，这正是"单继承 + 多实现"的典型写法。

```java
interface Flyable {
    int MAX_HEIGHT = 10000;                 // 隐式 public static final，是常量不是变量
    void fly();                             // 隐式 public abstract
    default void land() {                   // Java 8 起接口可以有带实现的方法
        System.out.println("landing");
    }
}

abstract class Bird implements Flyable {
    protected String name;                  // 抽象类能保存实例状态

    Bird(String name) {                      // 只有抽象类有构造方法
        this.name = name;
    }

    protected abstract void sing();          // 抽象方法可以是 protected

    public void description() {              // 共性实现写在父类里，子类直接复用
        System.out.println(name + " can fly");
    }
}

class Sparrow extends Bird {                  // 单继承抽象类
    Sparrow(String name) {
        super(name);
    }

    public void fly() {                       // 实现接口方法
        System.out.println(name + " flaps wings");
    }

    protected void sing() {                   // 实现抽象方法
        System.out.println(name + " chirps");
    }
}
```

## 常见追问

Q：Java 8 的默认方法出现后，接口是不是可以替代抽象类了？
A：不能。默认方法解决的是接口演进问题——给已有接口加方法时不破坏现有实现类。但接口依然没有构造方法、不能定义实例字段、不能保存对象状态，也无法把成员可见性降到 `protected` 以下。抽象类的能力里，只有"提供方法实现"这一项被接口追上了。

Q：一个类能同时继承抽象类又实现接口吗？
A：可以，而且这是最常见的组合。写法上 `extends` 必须在前、`implements` 在后，接口可以有多个。这样既复用了抽象类的实现与状态，又保留了被当作多种接口类型使用的能力。

Q：接口里能定义变量吗？
A：只能定义常量，隐式 `public static final` 且必须初始化。它属于接口本身，被所有实现类共享同一份，实现类改不了，也不能靠它给每个对象存状态。

Q：抽象类可以一个抽象方法都不写吗？
A：可以。这样它和普通类的区别只剩"不能被 `new`"，通常是给子类留扩展位的过渡形态。反过来，只要有一个抽象方法，类就必须声明成 `abstract`。

## 易错点

- 认为接口有了默认方法就等于抽象类。默认方法只补上了"能给实现"，补不上构造方法、实例字段和访问控制，这几件事只有抽象类能做。
- 把接口字段当普通变量用。它隐式是 `public static final`，写 `Flyable.MAX_HEIGHT = 1` 直接编译失败，而且所有实现类共享同一份值。
- 多接口同名字段或同签名默认方法时以为会自动合并。字段必须显式写成 `接口名.字段名` 才能消除歧义，同签名默认方法则必须由实现类重写来裁决冲突。
- 因为"以后可能加方法"就把接口改成抽象类。代价是子类从此单继承，别的父类再也继承不了，扩展性反而变差。

## 一句话记住

:::tip
接口管"能做什么"，可以多实现；抽象类管"共享什么"，只能单继承。
:::
