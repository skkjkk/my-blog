工具选择的本质是把「调不调、调哪个」当成一个**带校准的分类问题**：先给每个候选工具打分，得到 `p(tool_i | context)`，再加上一项「不调用任何工具、直接回答」的概率，然后在标注集上把模型过自信的原始分数校准成与真实正确率一致的置信度。只有校准过的概率才能当阈值用。在此之上，误调用（该不调却调了）朝**精确率**方向优化，漏调用（该调却凭记忆编）朝**召回率**方向优化，两者收敛在同一套反馈闭环里。

## 为什么不能直接用模型自报的概率

模型给出的选择概率是**严重过自信**的，这是整件事的起点。模型自报「八成把握」时，真实正确率往往明显低于八成，所以把自报概率直接当置信度去卡阈值，阈值就形同虚设。

校准要解决的是两件不同的事：**分类效果**（选得对不对）和**置信度可信度**（说的把握和实际正确率是否对得上）。一个准确率很高的路由模型，置信度照样可能完全没校准。

好在偏差是系统性的而不是随机的，所以可以在标注集上学一个单调映射，把原始分数映射到真实正确率。这样得到的置信度才能跨工具、跨上下文比较，也才有资格当阈值用；否则同一个自报「0.7」，在工具 A 上可能对应很高的实际正确率，在工具 B 上却可能差得很远。

## 四种原始信号与后验校准

可用的原始信号有四种，各有各的偏差，通常组合使用：

| 信号类型 | 说明 | 主要问题 |
|---|---|---|
| 生成 logprob 与熵 | 候选工具的生成概率分布及其不确定性 | 分布尖锐，概率尺度偏大 |
| 多次采样一致性 | 同一上下文多次采样，看选择是否稳定 | 采样成本高，且一致性不等于正确 |
| 自然语言自评 | 显式问模型对这次选择的把握程度 | 最过自信，只能当弱信号 |
| 独立审核调用 | 用一次独立的「审核」调用复核选择 | 多一次调用开销，但能纠错 |

流程是：这些信号先在标注集上做归一化，再用温度缩放、保序回归或 Platt 缩放做后验校准，输出与真实正确率一致的置信度。

:::note
评测要同时看校准误差和分类效果。工具选择错误的代价不对称时，更应看逐工具的精确率、召回率和混淆矩阵，而不只是整体准确率。
:::

标注数据要专门收集**语义相近的困难负例**，比如两个功能重叠的工具——「发邮件」和「发站内信」、「查订单」和「查物流」。这类样本决定了系统的上限：标注集里全是易分样本，校准曲线在中间区间就是空的，阈值根本无从谈起。

## 误调用：精确率怎么建模和优化

误调用指该不调却调了，或者调错了工具、参数错误。优化分三层做：

- **路由层隔离闲聊**：在「是否需要工具」这一层加一个独立判别器或路由层，把纯闲聊类问题先隔离掉，不让它们进入工具选择环节。
- **检索式筛选候选工具**：先用 embedding 把候选集缩小到少数几个，再让模型在小子集里选，避免工具数量膨胀导致的误选。
- **置信度阈值闸门 + 参数校验**：把置信度阈值作为可调闸门，阈值之上才执行，阈值之下走直接回答或向用户澄清，高风险写操作应该配更高的阈值。同时对工具参数做 schema 校验，校验不通过就不执行，而是回退并重试。

```python
def route(query, tools, tau_by_risk):              # 伪代码，阈值要按标注集调
    if not need_tool(query):                       # 路由层先隔离闲聊
        return answer_directly(query)
    candidates = retrieve_tools(query, tools, k=5)  # embedding 缩候选集
    scores = model.score_tools(query, candidates)
    p = calibrate(scores)                          # 温度缩放 / Platt / 保序回归
    tool, conf = max(p.items(), key=lambda kv: kv[1])
    if conf < tau_by_risk[tool.risk]:              # 按工具风险等级取阈值
        return ask_user(query)                     # 阈值下方澄清或直接回答
    args = model.fill_args(query, tool)
    if not schema_valid(args, tool.schema):
        return retry_with_feedback(query, tool, args)
    return call_tool(tool, args)
```

## 漏调用：召回率怎么建模和优化

漏调用指该调工具却直接编造答案，典型表现是模型凭记忆生成事实，没有任何检索依据，答案看着通顺但不可信。四个方向一起补：

- **上下文编码**：把「必须走工具」的信息编码进上下文，显式声明哪些类型的问题必须检索，而不是指望模型自己判断。
- **后置校验**：在生成答案之后做后置校验，检测答案中是否存在无法从已知上下文得到的事实，若存在则打回并强制走工具路径。
- **训练数据补充**：在训练数据中补充大量「需要外部信息」的正例，提高模型对工具必要性的敏感度。
- **失败切换**：在工具调用失败或返回空结果时，强制切换候选工具而不是草率放弃。

四条里后置校验最硬，因为只有它是直接检查「答案里有没有凭空生成的事实」；其余三条靠的都是提前把工具必要性注入上下文或训练先验。

## 一个统一闭环：风险分层阈值与反馈回流

置信度阈值不应该是全局常数，而应按工具的风险等级分层设置，高风险工具更保守、低风险工具更激进：不可逆的写操作（转账、删除、发消息）阈值高，只读查询阈值低，允许试错。

同时要把执行结果和用户纠正回流成反馈信号，按工具归因做在线校准，让每个工具拥有独立的置信度分布。理由是不同工具的调用频次和错误模式完全不同，全局一条校准曲线会把高频工具的行为平均到低频工具身上。

训练层面，推荐使用工具调用的结构化数据做监督微调，再用**执行成功率**而不是文本匹配作为强化学习的奖励，因为只有执行成功与否才能真正反映选择是否正确。

## 常见追问

**问：校准误差具体怎么度量？**
按置信度分桶，比较每桶的平均置信度与该桶的实际正确率，差距越小越校准；再画可靠性图看曲线是否贴近对角线。同时保留准确率、逐工具精确率/召回率和混淆矩阵，两套指标一起看。

**问：阈值该定高还是定低？**
取决于两类错误的代价比。误调用代价高（写操作、不可逆、有资损风险）就把阈值抬高，宁可多问用户一句；漏调用代价高（事实性问答、必须实时数据）就压低阈值，宁可多调一次工具。

**问：模型自己说「不需要工具」能信吗？**
不能单独信。自然语言自评是四种信号里最过自信的一种，必须配后置校验兜底：答案里出现了无法从上下文推出的事实，就打回并强制走工具路径。

**问：为什么一定要困难负例？**
因为误调用绝大多数发生在功能重叠的工具之间，易分样本上的校准曲线没有任何区分度，靠它调出来的阈值上线就废。

## 易错点

1. 把模型自报的把握程度直接当置信度用。自报概率严重过自信，必须先归一化再做后验校准，否则阈值只是心理安慰。
2. 只看整体准确率就调阈值。阈值是按工具设的，必须看逐工具的精确率、召回率和混淆矩阵，否则一个高频工具的误差会淹没低频高风险工具的误差。
3. 只治理误调用，不管漏调用。疯狂加阈值和校验会把系统从「乱调工具」逼成「该调也不调」，漏调用那一侧必须用上下文声明、后置校验、正例补充和失败切换一起补。
4. 评测集只覆盖常规样本。还要覆盖长尾问题、歧义表述、工具描述缺失或改写后的鲁棒性测试，以及新增或重命名工具后的稳定性测试——工具集一变动，旧的校准曲线就直接失效。

## 一句话记住

:::tip
置信度不能用模型自报的，校准过才敢拿它当阈值。
:::
