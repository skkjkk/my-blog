生产级 Agent 架构可以分成五层：**接入层、编排层、模型与能力层、状态与记忆层、基础设施层**，外加贯穿全系统的**可观测与治理**。下面按层说明关键模块。

1) **接入层（Gateway）**。提供 REST / SSE / WebSocket 接口，负责**鉴权、租户隔离、限流、请求校验、幂等键**。长任务需支持**异步提交 + 状态订阅**，因为 Agent 任务耗时长，不能用同步 HTTP 阻塞。

2) **编排层（Orchestrator）**。核心模块，包含：**任务状态机**（待运行/运行中/挂起/降级/完成/失败/取消/超时）、**任务依赖图调度**、**步骤执行与结果汇总**、**重规划触发**、**人在环节点**、**降级链**。这一层应当是**确定性的代码**，模型只做局部决策。

3) **模型与能力层**。包含：**模型路由器**（按难度与成本在多个模型间选择、支持级联升级）、**工具网关**（参数校验、权限裁决、限流、幂等、结果裁剪）、**检索服务**（向量库 + 关键词 + 结构化过滤 + 重排）、**子 Agent 管理**。

4) **状态与记忆层**。**工作状态**（任务树、子任务状态机、上下文、产物引用）存于**外部状态存储**（数据库 + 对象存储）；**长期记忆**独立成库（向量库 + 结构化表 + 知识图谱），带**写入筛选、检索、遗忘、冲突治理**四段机制。**真相在事件日志，视图可重建**。

5) **基础设施层**。**事件日志与 checkpoint**（支撑回滚与断点恢复）、**预算与配额守卫**（步数/token/时间/金额四重上限 + 预扣结算）、**密钥管理**（模型永不接触长期凭证）、**沙箱执行**（不可信代码）、**全链路追踪**（统一 trace id 贯穿）。

6) **可观测与治理**。**在线指标**（成功率、P95/P99 延迟、单任务成本、工具成功率、重复动作率、重规划次数、预算消耗）、**全量 trace + 采样**（失败任务全量记录）、**离线评测**（固定任务集回归门禁）、**成本归因**（把成本与成功率变化定位到具体环节）、**告警**（注入命中、越权尝试、预算异常、成功率突降）。

7) **生产化的四个关键取舍**。**成本与成功率的平衡** —— 用级联（便宜模型先跑、验证不过再升级）而非一味用强模型；**延迟与成功率** —— 独立子任务并行、渐进式披露结果；**自主与可控** —— 高危动作人在环、预算耗尽即降级；**可复现与灵活** —— 固定配置清单与录制回放，但允许模型版本灰度。

8) **最容易被低估的两个模块**。一是**上下文管理**（常被当作"简单拼接"，实则是质量与成本的主要来源）；二是**降级链**（决定系统在预算耗尽、依赖故障时的表现，决定"失败"是"明确失败"还是"静默错误"）。**这两个模块做得好，系统才是生产级的。**

9) **架构上的一条硬原则**。**副作用只能发生在工具网关**。所有外部写操作、代码执行、对外发送都必须经过它做权限与参数校验。这样系统的安全边界清晰、可审计，且未来要替换模型或框架时，核心资产（工具与状态）不受影响。
