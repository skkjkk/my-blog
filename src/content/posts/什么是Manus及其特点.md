Manus 是一款**通用的 AI Agent 产品**（面向终端用户，用户通过自然语言下达任务，Agent 自主完成并交付结果），由 2023 年成立于中国的团队 Monaci AI 开发，2024 年正式对外发布，被广泛视为"通用 Agent"这一产品形态的代表作之一。

1) **它最突出的产品特征是"交付物导向"**。不同于聊天式产品只给一段文字，Manus 会在自己的**云端沙箱环境**中执行任务，最终交付**成品** —— 报告、网页、表格、代码、可运行的应用、可交互的可视化看板。**"完成任务"而非"回答问题"**是它的核心主张。

2) **技术上是"多 Agent 架构"**。它把复杂任务拆解为若干专门角色协同：负责理解与拆解的**规划者（Planner）**、负责调用浏览器的**浏览者（Browser）**、负责写代码与运行程序的**执行者（Coder）**、以及负责整合产出的**报告者（Reporter）**。这种**角色分工 + 明确交接**的设计是 Manus 架构上最常被讨论的点。

3) **工具能力覆盖广**。浏览器操作、代码解释器执行、文件读写与生成、网页抓取、数据分析、图表绘制。**代码解释器是它的关键抓手** —— 把大量任务转成"写一段 Python 跑一下"，比逐个做专用工具更通用。

4) **面向长程任务做了专门的工程设计**。任务在后台异步执行，用户可以**中途查看进度、查看执行轨迹、随时中断或调整指令**，最终完成后收到通知。这种"**异步 + 可观测 + 可干预**"的交互形态，是长程 Agent 产品的必备设计。

5) **它把 Agent 的"上下文工程"作为核心竞争力**。长程任务必然超出上下文窗口，因此 Manus 在**任务规划、上下文压缩、文件作为外部记忆（用文件系统与文件引用承载中间产物）**上投入很大。**"用文件系统当 Agent 的硬盘"** 是其广为流传的做法。

6) **商业化路径与影响**。Manus 采用订阅制并曾以较高定价引发热议，一度成为"Agent 能力上限"的参照物。它的意义不只在于产品本身，更在于**验证了"通用 Agent + 异步交付"这个产品形态的可行性与付费意愿**，并对行业投融资与技术路线产生了明显影响。

7) **客观看待其局限**。**可靠性仍是主要短板** —— 长程任务累积的错误率不容忽视；**成本偏高**（多 Agent + 大量 token 消耗）；**对复杂专业领域**（需深度领域知识、需严格正确性的金融/医疗场景）仍需人在环；**可复现性弱**，同样输入结果可能不同。

8) **它对行业的真实贡献**。是把"**Agent 作为产品**"这件事推到了大众视野，并让"**交付物、异步、可干预**"这三条成为长程 Agent 产品的事实标准设计。同样重要的是，它让行业认清了**长程任务的核心瓶颈不在模型，而在上下文管理、任务分解与可靠性工程**。

9) **面试中怎么答**。重点讲四点即可：**产品定位（通用 Agent、交付物导向）**、**架构特征（多角色分工 + 云端沙箱 + 代码解释器）**、**长程任务工程（异步、可观测、可干预、文件系统作外部记忆）**、**局限与启示（可靠性与成本；瓶颈在工程不在模型）**。第四点最见功力，因为它说明你理解到了本质。
