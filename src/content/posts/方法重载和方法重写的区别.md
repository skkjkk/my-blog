两者都是 Java 多态的体现，但方向完全相反。**重载**发生在同一个类内部，用**参数列表不同**来区分同名方法，编译期就能确定调用哪一个，属于静态多态；**重写**发生在父子类之间，子类用**相同的签名**重新实现父类已有的方法，运行时由对象的真实类型决定调用哪个版本，属于动态多态。判断时抓两条主线：重载只看参数列表，重写看方法签名，再叠加访问权限和返回值类型的约束。

## 重载：同一个类里的同名方法怎么区分

重载指的是在同一个类里定义多个**方法名相同但参数列表不同**的方法。判定重载只看参数列表：参数**个数**不同、参数**类型**不同、参数的**排列顺序**不同，三者满足任一即为重载。如果方法名相同、参数列表也相同，那么无论返回值类型、访问修饰符、抛出的异常怎么改，都不构成重载；只改返回值的那份写法在 Java 里直接编译不过。

重载还有一个容易忽略的性质：它**允许发生在父子类之间**。子类新增一个与父类同名但参数列表不同的方法，也是一次重载；调用时编译器会把继承来的方法和子类声明的方法放在一起挑。所以「重载只能在同一个类里」是不严谨的说法，准确说法是**重载发生在同一个类的作用域内（含继承来的方法）**，而重写只发生在父子类之间。

## 重写：子类如何替换父类的行为

重写指的是子类对父类中**已有的方法**重新实现。它的约束比重载严格得多，签名必须一致，也就是方法名和参数列表都相同，此外还有三条：

- 访问权限不能比父类更严格，可以相同也可以放宽；父类 `public`、子类写成 `protected` 会编译报错。
- 返回值类型要么相同，要么是**协变返回**，即子类返回类型是父类返回类型的子类。
- 抛出的受检异常不能比父类更宽，可以更窄，也可以完全不抛。

有三类方法不参与重写：`final` 修饰的方法禁止重写，写了直接编译失败；`static` 方法属于类，子类再定义一个是**隐藏**而不是重写；`private` 方法对子类不可见，子类写一个同名同参的方法只是一个全新的方法，不会覆盖父类的实现。

## 代码：一眼看出绑定发生在哪个阶段

下面这段代码把重载、重写、静态隐藏、`final` 与 `private` 的限制放在同一个例子里，并故意注释掉几行编译不过的写法，方便对照记忆。

```java
class Calculator {
    int add(int a, int b) { return a + b; }              // 重载一：两个 int
    int add(int a, int b, int c) { return a + b + c; }   // 重载二：参数个数不同
    double add(double a, double b) { return a + b; }     // 重载三：参数类型不同
    // int add(int a, int b) { return 0; }  // 编译错误：参数列表一样，只改返回值不算重载
}

class Base {
    void hello() { System.out.println("Base"); }
    final void fixed() {}
    private void secret() {}
    static void stat() { System.out.println("Base static"); }
}

class Child extends Base {
    @Override
    void hello() { System.out.println("Child"); }        // 重写：运行期看对象的真实类型
    // void fixed() {}                                   // 编译错误：final 方法不能被重写
    void secret() {}                                     // 不是重写：父类 private 对子类不可见，这是新方法
    static void stat() { System.out.println("Child static"); } // 不是重写：静态方法只是隐藏
}

class Demo {
    public static void main(String[] args) {
        Base b = new Child();
        b.hello();   // 输出 Child       —— 动态绑定，看 new 出来的是谁
        b.stat();    // 输出 Base static —— 静态方法按引用的声明类型在编译期定死
    }
}
```

上面两行输出是理解两者的最短路径：重写的方法跟着对象走，重载和静态方法跟着**引用的声明类型**走。

## 一张表对比重载与重写

| 对比项 | 重载 Overload | 重写 Override |
| --- | --- | --- |
| 发生位置 | 同一个类内（含继承来的方法） | 父子类之间（含接口与实现类） |
| 判定依据 | 参数列表：个数、类型、顺序 | 方法签名：方法名 + 参数列表 |
| 返回值 | 不参与判定，可任意不同 | 相同或协变返回 |
| 访问权限 | 不受限制 | 不能比父类更严格 |
| 绑定时机 | 编译期，静态绑定 | 运行期，动态绑定 |
| 多态类型 | 静态多态 | 动态多态 |
| 受限制的方法 | 无特殊限制 | `final`、`static`、`private` 都不算重写 |

## 常见追问

**Q：为什么重载不能靠返回值类型区分？**
A：调用表达式 `add(a, b)` 本身不携带返回值类型的信息，编译器无法据此挑版本，所以语言层面直接禁止只改返回值的同名同参方法。反过来，如果允许，`int x = add(a, b)` 和 `double y = add(a, b)` 就会指向两个不同的实现，语义无法自洽。

**Q：重载的版本到底在什么时候选，会不会受运行时类型影响？**
A：在编译期就选定了，依据是**实参的静态类型**。把 `Child` 对象赋给 `Base` 引用后，若两边都有可匹配的重载，编译器按 `Base` 这个声明类型来挑，运行时不会改判；这一点和重写的动态分派正好相反。

**Q：重写之后还能调用父类的原实现吗？**
A：能，在子类里用 `super.method()` 显式调用，但它只能指向直接父类的实现，无法跨层跳到更上层；静态上下文里不能用 `super`。

## 易错点

- 以为「方法名相同、返回值不同」就是重载。实际上这是重复定义，编译期直接报错，重载的分界线只有参数列表。
- 以为重载也在运行期决定。重载是编译期的静态绑定，方法引用类型一变，选中的版本可能就变了，和对象真实类型无关。
- 把 `static`、`private`、`final` 的方法当成可重写。`static` 是隐藏，`private` 对子类不可见所以是新方法，`final` 则直接编译失败。
- 重写时把访问权限收窄，或者让受检异常变宽，这两种都过不了编译；放宽权限、收窄异常才是合法方向。

:::tip
重载在同类内、编译期按参数挑；重写在父子间、运行期按对象挑。
:::
