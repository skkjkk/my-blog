Computer Use 是让模型**能够直接操作图形界面**（浏览器、桌面软件）的一类能力：模型通过"**看屏幕 → 想动作 → 做动作 → 再看屏幕**"的循环，代替人类完成点击、输入、滚动等 GUI 操作。它把 AI 的能力边界从"API 空间"扩展到"整个操作系统"。

1) **原理是一个"感知-动作闭环"**。模型接收**屏幕截图**（视觉输入），输出**结构化动作**（如 `click(x, y)`、`type("text")`、`scroll(dx, dy)`、`key("enter")`），由外部的**执行器（Actor）**在真实屏幕上执行；执行后再截图回传给模型，**如此循环**直到任务完成或触发终止。**这是一个闭环，不是一次性的输出。**

2) **模型侧的三个核心能力**。**视觉理解** —— 识别界面元素、读出文字、理解布局；**空间定位** —— 把"那个蓝色的按钮"对应到具体坐标；**动作规划** —— 判断当前状态下该做什么、下一步做什么。**空间定位是最大的难点** —— 纯视觉模型的坐标精度有限，因此主流实现会叠加 **Set-of-Mark（SoM）**这类标注技术，在截图上标出可交互元素的编号与包围盒，让模型输出**元素 ID 而非裸坐标**，精度大幅提升。

3) **动作空间的设计**。早期是纯坐标驱动（`click(450, 320)`），现在主流转向**语义化动作**（基于无障碍树 accessibility tree 或 DOM 的元素引用），**可访问性树**尤其适合 Web 场景 —— 稳定性远高于像素坐标，且天然带元素角色与名称。

4) **"看屏幕"这一步有专门的工程优化**。**只截取变化区域**、**降采样与裁剪**、**文字用 OCR 提取避免视觉模型读小字**、**保留上一步的标注图避免重复标注开销**。这些是 Computer Use 能否落地成本与延迟的**决定性因素**。

5) **可靠性问题的根源是"状态假设错误"**。模型可能以为页面已经刷新、以为点击生效了，因此**必须在每个动作后重新观察并验证**（确认提示出现、页面内容变化），不能只凭一次输出连续执行多个动作。

6) **安全是头等大事**。这类 Agent 能点击任意按钮，因此必须**双重确认机制**（高风险动作执行前人工确认）、**动作白名单与区域限制**、**沙箱环境隔离**、**禁止访问生产数据与凭证**。Anthropic 官方明确把"提示注入"列为最大风险 —— 网页上的恶意文本可能诱导 Agent 泄露数据。

7) **典型代表**：Anthropic 的 **Claude Computer Use**（参考架构，跨桌面与网页）、**OpenAI 的 Operator / CUA**、**Google 的 Project Mariner**、各类 RPA 与 GUI 智能体产品。Anthropic 的官方实现采用**虚拟桌面 + 截图循环**，并强调"**不依赖特定系统、纯视觉**"以便跨平台。

8) **与 RPA 的本质区别**。RPA 靠**确定性规则与选择器**（写死流程，稳定但僵化）；Computer Use 靠**模型理解界面**，能应对界面变化，但**引入不确定性与不可复现性**。工程上常**结合使用** —— 固定高频流程用 RPA，界面多变、需要理解的部分用 Computer Use。

9) **与普通工具调用的区别**。普通工具调用是**结构化、精确、可枚举**的；Computer Use 的"工具"是**整个 GUI**，状态空间巨大、动作语义模糊、失败原因多样 —— 因此它**不是普通 Function Calling 的一个变体，而是一类需要专门工程方法（视觉定位、状态验证、沙箱）的技术**。

10) **成熟度判断**。它已能完成相当复杂的网页与桌面任务（表单填写、跨应用数据搬运、后台系统操作），但**长链条任务的累积误差**、**提示注入**、以及**细致操作（如拖拽、画图、复杂表格编辑）**仍是显著瓶颈。**目前最可靠的定位是"有人监督的自动化"，而非完全自主。**
