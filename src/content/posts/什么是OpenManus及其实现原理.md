OpenManus 是一个**开源的通用 AI Agent 框架**（2025 年由 Manus 社区的开源复现项目发起），目标是在开源环境下复现 Manus 那类"**通用任务执行 + 交付成品**"的 Agent 形态。理解它最好的方式是**把它与 Manus 对照**。

## 它与 Manus 的关系是"复现"而非"抄袭"

。Manus 本身是闭源商业产品，OpenManus 由社区在**分析其公开演示的行为特征**后，独立实现了一套等价架构。**它的价值在于把 Manus 那类"多角色 + 沙箱 + 长程任务"的工程设计公开化、可学习、可改造。**

## 核心是多 Agent 协作架构

。它把任务拆给若干**专门角色**：负责整体理解与任务分解的**规划者（Planner）**、负责调用工具的**执行者（Executor）**、负责信息获取的**浏览器操作者（Browser）**、负责产出文档的**报告者（Reporter）**、以及负责代码处理的**程序员（Coder）**。**角色之间通过结构化消息交接**，而不是共用一个上下文。

## "文件即外部记忆"是它的关键设计

。长程任务必然超出上下文窗口，OpenManus 的做法是**把中间产物写入工作区的文件**，上下文里只保留**文件路径与摘要**，需要时再读回。**这与 Manus 的思路一致，是长程 Agent 应对上下文限制最有效的通用手段之一。**

## 工具与执行环境

。内置**代码执行器**（写 Python 并真实运行，做数据分析、绘图、文件处理）、**浏览器自动化**（页面访问、交互、抽取）、**文件系统操作**、以及**多模型接入**（可配置不同角色使用不同模型 —— 强模型做规划、便宜模型做执行）。

## "通过用"来理解它的原理

。它的运行流程是：**接收任务 → 规划者拆解并写出计划（写入 plan 文件）→ 执行者按步骤调用工具 → 产出物落盘 → 报告者汇总生成最终交付物（报告 / 网页 / 表格）**。**注意"计划落盘为文件"这一点** —— 计划不是留在内存里，而是作为可读可改写的产物，这让它既能被人审阅和干预，也避免了计划随上下文被压缩而丢失。

## 它的工程启示

。**① 角色分离是上下文隔离的手段** —— 每个角色有自己的提示与上下文，避免互相污染；**② 产物外置比压缩摘要更可靠** —— 文件可以精确回读，摘要会丢信息；**③ 计划显式化**让长程任务可观测、可干预；**④ 交付物导向**让"完成"有了客观标准。

## 它的局限

。**多 Agent 带来显著成本**（每个角色独立上下文、独立调用）；**长程可靠性仍不足**（错误会随步骤累积）；**没有生产级的治理**（预算守卫、权限隔离、审计、优雅停机等在开源复现项目里通常较弱）；**评测与可复现性**不足。**它更像是一个很好的学习与实验基线，而非可直接上生产的框架。**

## 与主流框架的定位差异

。LangGraph 强在**可控的图式编排**；AutoGen/CrewAI 强在**角色对话**；ADK 强在**协议互操作与企业级**；**OpenManus 强在"把 Manus 式通用 Agent 的完整形态摊开给你看"** —— 它的教学价值与参考价值极高。

## 面试怎么答

1. 它是 Manus 的开源社区复现，核心是多角色分工（Planner/Executor/Browser/Reporter/Coder）
2. 关键技术是"文件即外部记忆 + 计划显式落盘"，这是长程任务突破上下文限制的关键手段
3. 它的价值在于把 Manus 式架构公开化便于学习与改造，但生产级治理仍需自己补齐
