包装类型就是基本类型的对象版本：基本类型直接存值、不能为 null、也没有任何方法；包装类型是堆上的对象，引用可以为 null，自带转换、解析、比较等方法。两者之间靠 Java 5 引入的自动装箱与拆箱自动互转，所以面试里真正的考点几乎都集中在这层自动转换上——null 拆箱抛空指针、双等号比的是引用地址、还有只覆盖小范围的装箱缓存。

## 两者到底是什么

Java 有八种基本类型：int、long、short、byte、char、float、double、boolean。它们是真正的基础类型，值直接存储，作为局部变量时值放在栈帧里（作为对象字段时随对象放在堆上），天然不可为 null，也不能携带任何方法。

Java 为每一种基本类型配了一个包装类：Integer、Long、Short、Byte、Character、Float、Double、Boolean。它们是普通的引用类型，是对象，存在堆上，引用可以指向 null，并且自带一组工具方法，比如类型转换、数值比较和字符串解析。类层次上这八个类并不共祖：Character 和 Boolean 直接继承 Object，其余六个继承 Number。

语义上两者的分工很清楚。基本类型表达的是"值"本身，语义天然完备，不存在"空"这个状态；包装类型表达的是"这个值所代表的对象"，因此可以额外表达"尚未赋值"这个状态。

## 关键差异对比

| 维度 | 基本类型 | 包装类型 |
| --- | --- | --- |
| 是否对象 | 不是对象，是值 | 是对象，是引用类型 |
| 存放位置 | 局部变量在栈帧，字段随对象在堆 | 对象本体在堆，变量持有引用 |
| 能否为 null | 不能 | 能，引用可以是 null |
| 成员变量默认值 | 0 / 0.0 / false / 空字符 `'\u0000'` | null |
| 能否调用方法 | 不能 | 能，valueOf、parseInt、equals 等 |
| 双等号比较 | 比较数值本身 | 比较引用地址 |
| 能否进集合泛型 | 不能，`List<int>` 不合法 | 能，`List<Integer>` |

## 自动装箱与拆箱

Java 5 之后引入了自动装箱与自动拆箱，编译器会在赋值、方法传参、返回值等位置自动补上 `Integer.valueOf(...)` 或 `intValue()`，源码里看起来是直接赋值，字节码里是一次方法调用。它是纯粹的编译期语法糖，运行时没有任何特殊照顾，所以性能和对象语义都要按"真的创建了对象、真的解了引用"来算。

```java
Integer a = 100;        // 自动装箱，等价于 Integer.valueOf(100)
int b = a;              // 自动拆箱，等价于 a.intValue()
List<Integer> list = new ArrayList<>();
list.add(1);            // 装箱后才能放进集合
int sum = 0;
for (Integer x : list) sum += x;   // 每次循环都拆箱
```

## Integer 缓存：-128 到 127

Integer 在自动装箱时对小范围数值做了缓存，默认范围是 -128 到 127，也就是 `Integer.valueOf` 命中缓存时直接返回同一个对象，不新建。这个上限可以通过 JVM 参数 `-XX:AutoBoxCacheMax` 调大，下限 -128 不可改。其余包装类的缓存是固定的：Byte、Short、Long 缓存 -128 到 127，Character 缓存 0 到 127，Boolean 干脆只有 TRUE 和 FALSE 两个常量。

这既是性能优化，也是很多比较陷阱的根源：同样写 `==`，值在缓存范围内恰好为真，超出范围就变成假，看起来像"时灵时不灵"。

## 装箱是有成本的

每装箱一次就产生一个对象，循环里大量装箱会带来额外的内存分配和垃圾回收压力。典型场景是拿包装类型当循环累加器：`Long total = 0L;` 然后在循环里 `total += x`，每一轮都要拆箱再装箱，白白造出一堆临时对象。改成基本类型局部变量累加、最后再装箱一次就够。集合装不下基本类型，`ArrayList<Integer>` 里每个元素本质上都是一个对象加一个引用，这也是大数据量下优先考虑基本类型数组的原因。

## 什么时候用哪个

- 基本类型是默认选择：纯粹的数值计算、方法内部的临时变量、性能敏感的字段存储，都用它。
- 包装类型用于集合和泛型：集合与泛型在类型设计上不接受基本类型，`Map<String, Integer>` 必须写包装类型。
- 需要表达"可能为空"时用包装类型：数据库映射的字段（SQL 的 NULL 只能落到包装类型上）、可选的请求参数、缓存的键、序列化场景。
- 需要用到包装类的方法时用包装类型：字符串解析、进制转换、类型比较等。

## 常见追问

Q：Integer 和 int 的默认值不一样，为什么这很重要？
A：成员变量层面，int 默认是 0，Integer 默认是 null。用 0 表示"没填"会把"用户填了 0"和"用户没填"混成一件事，所以数据库字段、可选参数这类要区分"空"和"零"的地方必须用包装类型。

Q：为什么 `Integer a = 127, b = 127` 时 `a == b` 是 true，换成 128 就变成 false？
A：因为自动装箱走的是 `Integer.valueOf`，-128 到 127 命中缓存返回同一个对象，所以引用相等；128 超出缓存范围，两次装箱各造一个对象，引用自然不等。这恰好说明 `==` 比较的是地址而不是数值。

Q：三目运算符为什么会莫名其妙抛空指针？
A：当两个分支一个是基本类型、一个是包装类型时，编译器会把结果类型统一提升为基本类型，于是对包装类型那一支做拆箱；如果它恰好是 null，运行时就抛空指针。规避办法是两支类型保持一致，或者显式判空。

## 易错点

- 把 null 的包装类型当基本类型用就会抛空指针。`Integer n = null; int x = n;` 以及 `if (n == 1)`、`int r = n + 1` 都隐含拆箱，都会抛 NullPointerException；先判空或改用 `Integer.valueOf(1).equals(n)` 这类写法。
- 用双等号比较包装类型。`==` 比的是引用地址，只有命中缓存且是同一个对象时才为真。比较数值一律用 `equals`，或者先转成基本类型再比。
- 以为缓存范围对所有包装类都一样大。默认的 -128 到 127 只属于整型（其中 Integer 的上限还能调大），Character 只缓存 0 到 127，Boolean 只有两个常量，Float 和 Double 根本没有缓存。
- 用 `new Integer(1)` 造对象。包装类的构造方法在新版 JDK 里已被标记为废弃，直接用字面量或 `valueOf` 即可，还能顺带吃到缓存。

## 一句话记住

:::tip
包装类型是对象、可为 null；基本类型是值、不能为 null，比较用 equals。
:::
