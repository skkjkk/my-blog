Java 有八种基本类型，分别是 int、long、short、byte、char、float、double 和 boolean，它们是真正的基础类型，局部变量存放在栈上，值直接存储，天然不可为 null，也不能携带任何方法。除此之外 Java 为每一种基本类型提供了一个对应的包装类，也就是 Integer、Long、Short、Byte、Character、Float、Double 和 Boolean，它们是普通的引用类型，是对象，存在堆上，引用可以指向 null，并且自带一组工具方法，比如转换、比较和解析。

两者最直观的区别体现在语义和用途上。基本类型表达的是"值"本身，语义上天然完备，不存在"空"这个状态；包装类型表达的是"这个值所代表的对象"，因此可以表达"尚未赋值"这个状态。历史上这八种包装类都继承自同一个 Number 或者 Object 类，Java 5 之后引入了自动装箱与自动拆箱，编译器会在赋值和方法传参时自动完成互转，这极大地方便了编写，但同时也埋下了几个经典的坑。

第一个坑是空指针异常。当一个包装类型的引用是 null 时，一旦发生自动拆箱，运行时就会抛出空指针异常。第二个坑是相等判断。包装类型之间用双等号比较的是引用地址而不是数值，只有在自动装箱命中缓存且是同一个缓存对象时才恰好为真，正确做法是使用 equals 或者先转换成基本类型再比较。还有一个隐蔽的坑是三元运算符，当两个分支一个是基本类型一个是包装类型时，编译器会统一做拆箱，如果此时包装类型为 null，同样会抛空指针。

第三个差异是缓存机制。Integer 在自动装箱时会对小范围的数值做缓存，默认是负 128 到 127，同一个值装箱后往往得到同一个对象，这既是性能优化也是很多比较陷阱的根源。另外装箱本身是有成本的，每装箱一次都会产生一个对象，在循环中大量装箱会带来额外的分配开销和垃圾回收压力。

最后是使用场景的划分。基本类型用于纯粹的数值计算和字段存储，是默认选择；包装类型用在集合和泛型中，因为集合和泛型在类型设计上不接受基本类型；也用在任何需要表达可能为空或者需要调用方法的场合，比如三元表达式的结果、数据库映射的字段、缓存的键以及序列化场景。
