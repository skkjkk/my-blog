Reflexion 是一种给 Agent 加入**"自我反思与试错学习"**机制的范式。它在 ReAct 的基础上增加了第三种输出类型：**Reflection（反思）** —— 在任务执行过程中或失败之后，模型对刚才的行为做一次归因分析，把经验写进外部记忆，下一次尝试时把这段经验作为额外上下文带入，从而实现**跨轮次、跨任务的自我改进**。

1) **与 ReAct 的核心区别**。ReAct 的轨迹只有 Thought、Action、Observation 三种元素，**只在当前任务内做局部修正** —— 看到错误结果就换个动作再试，但**经验不沉淀、不会跨任务复用**。Reflexion 增加了 Reflection 这一环，把失败原因**显式地写成文字经验并持久化**，从而让 Agent 在后续尝试中**避免重复同类错误**。

2) **ReAct 是"当前任务内纠错"，Reflexion 是"跨任务改进"**。这是最精准的一句话区分，也是面试中应当先给出的答案。

3) **三种触发时机**。**行动前反思**（Act-Reflect-Act 循环中，在每次动作前先评估当前方案是否合理）、**行动后反思**（得到结果后总结成功或失败的原因）、**任务后反思**（整体完成后的总结与经验沉淀）。工程上最常用的是后两种。

4) **Reflexion 的经典实现是一个 Actor-Critic 双角色结构**。Actor 负责产生动作，Reflector 负责生成反思文本，记忆模块存储反思，轨迹在反思后被**截断重写**（把反思文本插入轨迹作为新一轮的引导）。注意这里 Critic 不是打分器，而是**生成改进建议的另一个角色**。

5) **提升自我纠错能力的通用手段**。一是**可诊断错误回填** —— 工具失败时把具体原因（不是堆栈，而是"参数 x 不存在，请用 id 字段"）交给模型；二是**外部验收** —— 用程序化断言或独立评判器判定成败，而非模型自述；三是**失败模式归类** —— 把错误归入"选错工具/参数错/理解错/环境异常"，不同类别给不同的引导提示；四是**经验注入** —— 把历史失败经验压缩成简短规则放在提示开头；五是**重规划触发** —— 连续失败 N 次时跳出局部循环，重新分解任务。

6) **它的代价与风险**。反思本身要**消耗一次额外的模型调用**（延迟与成本上升）；反思质量取决于模型能力，**弱模型可能生成错误归因，反思错了比不反思更糟**；反思文本会占用上下文窗口；过度反思会让 Agent 反复怀疑自己、迟迟不行动。实践上要给反思**次数上限**与**触发条件**（比如只在连续失败或验收不通过时触发），而不是每步都反思。

7) **与 Plan-and-Execute 的关系**。Reflexion 改进的是"**单次尝试的质量**"，Plan-and-Execute 改进的是"**长程结构**"。两者不冲突，生产上常组合：外层用规划-执行分离控制结构，内层用 Reflexion 处理局部失败。
