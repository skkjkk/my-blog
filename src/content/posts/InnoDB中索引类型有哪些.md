InnoDB 支持 **6 种索引类型**，但真正日常用的是前两种。**面试时按"数据结构"分类最清晰**。

1) **⭐ 聚簇索引（Clustered Index）—— InnoDB 的默认组织方式**
叶子节点存放**整行数据**，数据与索引在**同一棵 B+ 树**上。每张 InnoDB 表**有且仅有一个**聚簇索引。
- **InnoDB 会自动选一个**（优先级）：**显式主键 > 第一个非空唯一索引 > 隐藏的 6 字节 `DB_ROW_ID`**
> **⚠️ 所以不指定主键 = 用隐藏自增 ID → 所有二级索引都要存这 6 字节，且分库分表时全局唯一性靠它不靠谱。**

2) **⭐ 二级索引（Secondary Index）—— 用的就是 B+ 树**
叶子节点存放**索引列值 + 主键值**。查其他列时需**回表**到聚簇索引。
- **回表是随机 IO** → 大量回表可能比全表扫描还慢 → **覆盖索引**是优化关键

3) **⭐ 哈希索引（Hash Index）**
- **⚠️ InnoDB 的 Hash 索引是"自适应哈希索引"，用户不能手动创建** —— InnoDB 会**自动**为频繁等值查找的页建立哈希索引来加速
- **MySQL 8.0 支持** `CREATE INDEX ... USING HASH` 手动创建（InnoDB）
- **缺点**：**不支持范围查询、不支持 ORDER BY、不支持最左前缀** → 只适合纯等值查找

4) **⭐ 全文索引（Fulltext Index）**
`FULLTEXT`，支持 `MATCH AGAINST` 关键词检索。
- 支持自然语言模式（`IN NATURAL LANGUAGE MODE`）、布尔模式（`IN BOOLEAN MODE`）
- **⚠️ 中英文分词问题**：默认按**空格**切词 → **中文几乎不可用** → 需应用层分词（如 IK）或改用 **Elasticsearch**
- InnoDB 从 **5.6 起**支持；**中文建议用 ngram 全文解析器**（MySQL 5.7+）

5) **空间索引（Spatial Index）**
基于 **R-Tree**（R 树）实现，用于**地理空间数据**的检索（经纬度、多边形范围查询）。
- 空间类型：`POINT`、`LINESTRING`、`POLYGON`、`GEOMETRY` 等
- 必须字段类型为 `NOT NULL` 且带 `SRID` 属性

6) **多列索引（Composite / Multi-column Index）**
即**联合索引**，由多个列组成，是**最常用**的类型。
- **遵循最左前缀原则**
- **覆盖索引**：查询列全在联合索引内 → 不回表
- **等值 + 范围**：范围列之后的列**无法继续用于索引查找**（但仍会存入索引）

7) **⭐ 补充：前缀索引（Prefix Index）**
对字符串列只索引前 N 个字符：`KEY idx_name (name(10))`。
- **用途**：列很长（`TEXT`/长 `VARCHAR`）时控制索引大小
- **⚠️ 限制**：**不能用于覆盖索引**、**排序**（需完整列）、**唯一约束**
- **⚠️ 区分度会降低**：`name(10)` 前 10 字符相同占比高 → 效果差

8) **⭐ 按"数据结构"归类（面试更清晰的答法）**
- **B+ 树** → 聚簇索引 + 二级索引 + 联合索引 + 前缀索引（**InnoDB 的绝对主力**）
- **B 树** → MyISAM 的主键索引（**InnoDB 不用 B 树**）
- **哈希** → Hash Index
- **倒排索引** → 全文索引（MySQL 内部实现，⚠️ **不是 Lucene 那种真正的倒排**）
- **R-Tree** → 空间索引

9) **面试答法建议**。三点：**① 六种类型列全（聚簇/二级/哈希/全文/空间/多列），并强调"聚簇索引每表唯一 + 二级索引叶子存主键值"；② 关键差异点（哈希不支持范围与最左前缀；全文索引中文分词不可用；InnoDB 的哈希索引是自动的自适应哈希、用户不能手动建）；③ 落到"实践高频的其实是 B+ 树家族的四种，前缀索引不能用于覆盖索引与唯一约束"**。**第二点的"自适应哈希不能手动建"是区分度最高的细节。**
