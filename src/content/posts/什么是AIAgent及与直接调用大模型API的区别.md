大模型 API 调用是"一问一答"：把提示词发过去，模型返回一段文本，调用结束，开发者自己去解析、去调工具、再把结果发回去。而 AI Agent 是在这个基础上加了一个**能自主循环决策的运行时**：模型不只是生成文字，而是根据目标**自己决定下一步做什么、调用哪个工具、观察结果、再继续想**，直到目标达成或触发终止条件。

## 本质区别是控制权的归属

。直接调 API 时，**控制流在开发者代码里**，开发者规定好每一步；Agent 模式下，**控制流交给模型**，开发者只提供目标、可用工具和边界条件，由模型在运行时动态规划路径。

## Agent 具备四个核心能力

，这是它与裸 API 的分水岭：**感知**（读取环境与工具返回）、**决策**（规划下一步动作）、**执行**（调用工具并作用于环境）、**记忆**（跨步骤保留状态与历史经验）。裸 API 调用只有"生成"这一项。

## 引入了循环与状态管理

。Agent 通过 Agent Loop 反复"思考 → 行动 → 观察"推进任务，这带来两个裸 API 没有的问题：**上下文如何随步数增长而管理**，以及**如何判断任务完成、防止无限循环**。

## 引入了工具与副作用

。裸 API 调用通常只返回文本，Agent 会真实调用数据库、文件系统、外部服务，因此必须处理**超时、失败、权限、幂等、副作用**这些工程问题。

## 引入了自主性的风险

。正因为控制流交给了模型，同样的输入可能走出不同的路径，带来**可复现性下降、成本不可预测**（步数不定）、以及**越权与注入风险**。裸 API 调用的行为是确定的。

## 价值与成本的取舍

。Agent 适合**步骤数无法预先确定、且需要与环境交互**的任务（排障、深度检索、代码修改、运维操作）；如果流程固定、步骤已知，**直接调 API 反而更好** —— 更快、更便宜、更可控、更易测试。这是选型时最重要的判断。

## 工程上的分层实践

。成熟做法是**混合式**：把确定性强的部分用普通代码写死，把需要灵活判断的部分交给模型做局部决策，而不是把整个流程都变成 Agent。判断标准是"**这一步是否真的需要自主推理**"。
