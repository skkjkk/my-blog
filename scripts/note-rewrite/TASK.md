# 笔记改写任务（给子智能体）

你在维护 `D:\06-Agentworkspace\my-blog` 这个技术面试题库博客。用户抱怨：**刷题页点开答案，答非所问、只答一点、不像一篇完善的博客**。
根因是笔记本身结构不行——题库的答案就是从笔记正文里抽的（`src/utils/quiz-utils.ts`）。

## 你的任务

把指定的一篇笔记，按 `docs/note-standard.md` 的规范重写一遍，让它成为一篇**结构完整、内容准确、能直接当面试答案背**的技术笔记。

## 流程（照做）

1. 读 `docs/note-standard.md`（规范，先读，别凭印象）。
2. 读目标笔记原文（路径在任务里给出）。
3. 需要时读同分类另外 1–2 篇已被评为 A 级的笔记，对齐风格和密度：
   `node scripts/note-quality.mjs --grade A --top 5` 能看到 A 级清单。
4. 写新版本到 `.tmp/rewrite/<文件名>`（**必须是这个目录，不要直接改 src**）。
   - 保留原 frontmatter 全部字段，只允许：补全/重写 `description`（30–70 字，完整一句话，不留「…」截断），其他字段一字不动。
   - 正文按规范：首段结论（60–200 字，第一句就回答问题）→ 3–7 个 `##` 小节 → 至少一处示例（代码/表格）→ `## 常见追问`（2–4 组，**必须写成 `**问：…**` 换行 `**答：** …` 这种一问一答两行**，刷题页靠它解析）→ `## 易错点`（2–4 条）→ `## 一句话记住`（`:::tip` 包起来，≤40 字）。
5. 自检：`node .tmp/rewrite/check-one.mjs <你的文件>`（会打印分数和问题清单），**分数必须 ≥85 且问题清单里不能有红线类**；不达标就改，改完再跑。
6. 达标后，用 3–6 行中文说明你改了什么（哪些事实是原稿的、哪些是你补的、有没有改正原稿的错）。

## 事实纪律（最重要）

- 原稿里的技术判断、结论、类名、参数名、场景**必须保留**，可以重排与补充解释，不许丢。
- 不许编造版本号、性能数字、benchmark、论文结论、公司内部做法。不确定就写定性描述。
- 原稿有**明显技术错误时必须改正**（例如把 `wait` 说成不释放锁、把 `HashMap` 说成线程安全），并在正文里讲清正确说法。
- 宁可少写一节，也不要写空话凑字数。**不要出现乱码、错字、把中英文粘在一起的无意义词**（生成后自己通读一遍，这是硬要求）。

## 硬性禁止

- 不改 `src/` 下任何文件（除非任务明确说"直接改"）。
- 不写一级标题 `#`。
- 段落/小节正文开头不能是「。」「，」「；」「：」。
- 不用 `1) 2) 3)` 老式编号。
